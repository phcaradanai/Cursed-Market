# วิธีอ่านกราฟเส้น: สินค้าใหม่ 56 ชิ้น ↔ effect ↔ logic ↔ ทรัพยากร

อัปเดต 2026-10-28 · ขอบเขต merchant-set-v1 ใหม่เท่านั้น

เปิด [หน้า relation เดิม](logic-item-relations.html) แล้วเลือก **กราฟเส้นเชื่อม** สลับกลับ **ตาราง Matrix เดิม** ได้โดยไม่เปลี่ยนข้อมูลสินค้า

## สีและชนิดของจุด

| จุด | สี / รูปแบบ | ความหมาย |
|---|---|---|
| สินค้า | เหลือง กรอบหนา | สินค้าใหม่จากแค็ตตาล็อก 56 ชิ้น |
| Effect | ม่วง | E01–E75; มีทั้งแนวที่เลือกใช้ในร่างและที่ยังว่าง |
| Logic | ฟ้า | ระบบ L01–L33 พร้อมจำนวนสินค้าหลัก/ตัวรองที่เกี่ยวข้อง |
| ทรัพยากร | เขียว | ชีวิต พลัง เงินใช้จ่าย เงินต้นในคลัง ช่องคลัง สินค้า เศษ หนี้ ตรา และคะแนน |
| พ่อค้า | เทา | กลุ่มแค็ตตาล็อก เปิดแสดงได้; ไม่ใช่เจ้าของ instance ระหว่างเกม |
| จุดทบทวน balance | ส้ม | ความกว้าง หน้าที่ซ้ำ และวงจรที่ต้องตรวจ ไม่ใช่ความเสียหายที่เกิดขึ้นแล้ว |

## สีและลักษณะเส้น

| เส้น | ความหมาย |
|---|---|
| เหลืองหนา P | หน้าที่หลักที่เสนอให้สินค้า |
| เหลืองบางจุด S | ตัวรองที่ยังเลือกตัดได้ ไม่ใช่อนุมัติให้ใส่ทุกอย่าง |
| เขียวทึบ | ประโยชน์/ตัวปรับที่เสนอ หรือผลดีของระบบเมื่อเกิด trigger |
| **แดงเส้นประ** | ต้นทุนหรือผลเสียตามเงื่อนไข เช่น จ่ายชีวิตทำสัญญาเลือด เสียพลังเริ่มขโมย จ่ายเงินซื้อของ หรือแพ้ทายเหรียญ |
| ฟ้าจุด I | เชื่อมทางอ้อม เช่น เสริมสกิล Swarm แล้วไปเกี่ยวกับการสร้างสำเนา |
| เทา ↔ | โอนทรัพยากร เช่น เงินใช้จ่ายไปเงินฝาก ไม่ใช่ทรัพยากรสูญหาย |
| เทาจุด | แนว effect ในคลังที่ยังไม่มีสินค้าเลือกใช้ |
| ส้มจุด | เชื่อมกับข้อควรทบทวน balance |

เครื่องหมายลบไม่ได้เป็นผลเสียเสมอ เช่น **ลดหนี้** เป็นประโยชน์และใช้เส้นเขียว สีเส้นอิงความหมาย ไม่ใช่ตรวจคำว่า “ลด” อย่างเดียว

## ข้อสำคัญ: ความเกี่ยวข้องไม่เท่ากับผลที่เกิดทุกครั้ง

เส้นสินค้า → effect เป็น **ร่างการจัดหน้าที่** ยังไม่มี dedicated runtime binding ของสินค้าใหม่ที่ยืนยันได้ เส้น logic → ทรัพยากรเป็น **บริบทของระบบ** ซึ่งมีเงื่อนไขกำกับ ไม่ใช่ drawback ที่กำหนดให้สินค้าทุกชิ้นที่โยงถึง

ตัวอย่าง **ขวดรินไวน์เงา → E58 ลดค่าชีวิตสัญญาเลือด → สัญญาส่วนตัว NPC → เส้นแดงจ่ายชีวิต**:

- E58 เสนอให้ **ลดต้นทุนที่มีอยู่** จึงเป็นตัวปรับเชิงบวก
- เส้นแดงเป็นต้นทุนของการเลือกทำสัญญาเลือด ไม่ใช่การซื้อหรือถือขวดแล้วเสียชีวิตทันที
- กลุ่ม L22 ยังมีสัญญา Alien ด้วย ปลายทางผลตอบแทนสัญญา Alien ไม่ได้แปลว่า E58 เพิ่มผลตอบแทน Alien ต้องอ่านเงื่อนไขแต่ละเส้น
- ผลเสียเฉพาะรายชิ้นของสินค้าใหม่ 56 ชิ้นยังไม่ได้ออกแบบ จึงไม่มีการสร้างข้อเสียใหม่ให้ครบทุกชิ้นเพียงเพื่อเติมเส้นแดง

Tooltip ของแต่ละจุดและเส้นระบุประเภท บทบาท เงื่อนไข จำนวนที่รู้ และสถานะกฎ/ข้อเสนอ คลิกเส้นเพื่อปักรายละเอียดและกดตามจุดต้นทางหรือปลายทางต่อได้

## วิธีตามหาและเปรียบเทียบ

1. ค้นชื่อสินค้า, ID, E46, L22 หรือทรัพยากร เช่น “ชีวิต” แล้วเลือกผลค้นหา
2. คลิกสินค้าเพื่อดู effect และระบบปลายทาง คลิก effect เพื่อย้อนหาสินค้าอื่นที่ใช้ร่วมกัน
3. คลิก logic เพื่อดูสินค้าที่เกี่ยวข้อง หรือคลิกทรัพยากรเพื่อย้อนดูหลายระบบที่แตะมัน
4. กรองพ่อค้า ระยะ 1/2 ชั้น หรือทั้งเส้นทาง เพื่อไม่ให้เห็นทุกจุดพร้อมกันจนอ่านยาก
5. ปิดตัวรอง S เพื่อดู coverage ที่เหลือจากหน้าที่หลักเท่านั้น
6. เปิดจุดเสี่ยง balance เพื่อเห็นสินค้าที่กว้าง ชุดซ้ำ และวงจรเร่งทุน/พลัง/คะแนน
7. เพิ่มสินค้าสองชิ้นเข้า “คู่เปรียบเทียบ” เพื่อดู logic ร่วม effect ซ้ำ และเส้นทางรวมของสองชิ้น
8. ลากพื้นที่ว่างเพื่อเลื่อน กด Ctrl/⌘ ร่วมกับล้อหรือใช้ +/− เพื่อซูม (ล้อปกติเลื่อนหน้าเอกสาร) ใช้ปุ่มพอดีกรอบ/อ่านตามความกว้างตามต้องการ
9. ใช้ Tab/Enter เพื่อโฟกัสและเปิดจุด; tooltip เปิดจาก focus ได้; Esc ปิด tooltip; เมื่อโฟกัสพื้นที่กราฟ ใช้ลูกศรเลื่อน และ 0 คืนขนาดพอดี
10. บันทึกกราฟ SVG ของส่วนที่กำลังดู หรือดาวน์โหลด CSV เส้นทั้งหมดไปวิเคราะห์ต่อ

ค่า “สินค้าเชื่อมตรง” ใน tooltip เป็นจำนวนจากร่างเต็ม ส่วนแถบบนกราฟเป็นจำนวนที่เห็นในตัวกรองปัจจุบัน จึงอาจไม่เท่ากัน

## ตัวอย่างที่ช่วย review

- **E46 / ดอกเบี้ย:** ย้อนดูแหวนตราราตรีกับทุ่นแก้วคลื่น ตรวจว่าการเชื่อมเงินกู้/ประกันทำให้ทุนโตปลอดภัยเกินไปหรือไม่ ฐาน 10% ยังต้องใช้เงินต้นครบช่วง
- **E16 + E64:** เทียบกลองศึกกระดูกกับอานสาหร่ายที่มีชุด effect ซ้ำ
- **L21 Collector Wishlist:** ไม่มีสินค้า modifier ตรง แต่มีต้นทุนเงินซื้อและผลได้สินค้าเป็นบริบทของกฎ 3+2 / รอ 2 turn / เปิดดู 1 / จ่ายจริง
- **L30 คะแนนพิเศษ:** แยกรางวัลผู้นำ ×2=20 และ ×3=40 ออกจากมูลค่าคะแนนฐาน ไม่เพิ่มคะแนนให้สินค้าทุกชิ้นเอง
- **ชีวิต:** แยกสัญญาเลือด การรักษา เศษชีพจร และภัยพายุ อย่านับว่าทุกต้นทางเสียชีวิตพร้อมกัน

- จำนวนเส้นกราฟมากกว่าตารางสินค้า เพราะรวมบริบทและกลุ่มข้อมูล ต้องกรอง `role` ก่อนนำไปนับว่าชิ้นไหนเชื่อมมาก
- จำนวนจุด/เส้นไม่ใช่คะแนนพลัง ยังไม่มีการจำลองราคา โอกาส ชาร์จ หรืออัตราชนะ

การแก้ relation canonical JSON ภายหลังต้องปรับ graph dataset และข้อมูลฝังใน HTML ให้ตรงกันก่อนอ้างว่าเป็น snapshot เดียวกัน มี `sourceDatasetSha256` ใน Graph JSON สำหรับตรวจแหล่งข้อมูล
