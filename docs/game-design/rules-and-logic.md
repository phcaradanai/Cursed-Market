# Cursed Market — กฎและ logic เกม

อัปเดต: 2026-10-28 (Asia/Bangkok)

อ่านคู่กับ [คลัง effect](effect-catalog.md) และ [สารบัญ](README.md)

## 1. สถานะเอกสารและลำดับกฎ

เอกสารนี้รวบรวม logic เดิมที่ตรวจจากซอร์สและกฎใหม่ที่ผู้ใช้ระบุ ไม่ใช่รายงานว่าพัฒนาเสร็จแล้ว

| สถานะ | ความหมาย |
|---|---|
| ยืนยันล่าสุด | ผู้ใช้กำหนดโดยตรงในการสนทนาวันที่ 2026-10-28 |
| มีในโค้ด | ตรวจพบกลไกจากซอร์สใน repository แต่ไม่รับรองว่าเปิดในทุกห้องหรือเชื่อมครบใน UI comic |
| ข้อเสนอ | วิธีทำ ตัวเลข หรือกรณีขอบที่ผู้ช่วยเสนอ ยังไม่ใช่กฎที่ยืนยัน |
| ยังไม่ตกลง | มีความกำกวมหรือยังขาดค่าที่ใช้พัฒนาได้แน่นอน |

หากขัดกัน ให้กฎ **ยืนยันล่าสุด** มีลำดับเหนือโค้ดเก่าและข้อเสนอ effect วันที่ 2026-10-26 ตัวอย่างที่ถูกแทนที่: ดอกเบี้ย 4%, ข้อเสนอเพดานดอกเบี้ยรวม 8% และ effect ปฏิเสธ/ยกเลิกการดวลขโมยโดยอัตโนมัติ

## 2. คำศัพท์และเวลา

- **Phase**: ขั้นย่อย เช่น เลือกพ่อค้า ประเมิน ซื้อขาย หรือรับรางวัล
- **Encounter / ช่วงพบพ่อค้า**: หนึ่งรอบที่ประกอบด้วยหลาย phase
- **Turn**: ในตัวอย่างเอกสารนี้ใช้เป็นหนึ่ง encounter เพื่อให้เห็นเวลาอย่างต่อเนื่อง ผู้ใช้ยืนยันจำนวน 2 turn แต่การผูกกับ phase จริงต้องยืนยันก่อนเขียน scheduling
- **Collector รอบ Wishlist**: นำสินค้าที่ขอไว้มาเสนอขาย เป็นคนละหน้าที่กับ Collector ตัดสินคะแนนตอนจบ
- **เงินก้อนเดิม**: เงินต้นที่ฝากและคงอยู่ครบระยะรับดอกเบี้ย ไม่รวมเงินที่เพิ่งเติมหรือถอนแล้วฝากกลับ
- **ประเภทสินค้า / kind**: ชนิดสินค้า เช่น สินค้าหนึ่งแบบในแค็ตตาล็อก
- **ชิ้นสินค้า / instance**: สินค้าจริงแต่ละชิ้น มีเจ้าของ ราคาซื้อ สถานะ และ rarity ของตัวเอง
- **ชีวิตที่เสีย** และ **การเสียชีวิต**: จำนวนหน่วยชีวิตที่ลด กับจำนวนครั้งที่ตาย เป็นคนละสถิติ ห้ามนำมาปนกันโดยไม่ยืนยัน

## 3. ภาพรวมเกมและ logic ที่มีอยู่

ตารางนี้ระบุกลุ่มระบบที่พบในซอร์ส ไม่ได้หมายความว่ากฎใหม่ทั้งหมดในเอกสารถูกนำไปใช้แล้ว

| ระบบ | Logic / ข้อมูลหลัก | ข้อจำกัดสำคัญ |
|---|---|---|
| ลำดับรอบ | เลือกประตู → ประเมิน/ซื้อ → ซื้อขาย → รับรางวัล → รอบถัดไป → จบเกม | Action ต้องตรง phase; คำสั่งซ้ำไม่ควรทำผลซ้ำ |
| สินค้า | เจ้าของ ชนิด ความแท้ คำสาป มูลค่า ข้อมูลที่แต่ละคนรู้ ราคาซื้อ/ราคาธุรกรรม และ rarity | หน้าตาคล้ายกันไม่ได้แปลว่าเป็น instance เดียวกัน |
| ตรวจและตีราคา | ตรวจมูลค่า ความแท้ คำสาป; ประเมินและต่อราคา | ข้อมูลที่ยังไม่รู้ต้องไม่รั่วผ่าน UI หรือข้อมูลส่งให้ผู้เล่น |
| สิทธิ์ฟรี | กฎเดิมมีหนึ่ง action ฟรีร่วมกันต่อสินค้าพ่อค้า สำหรับตรวจหรือประเมิน | ใช้ตรวจแล้วไม่ควรได้รับสิทธิ์ประเมินฟรีเพิ่มจากสิทธิ์เดียวกัน |
| ซื้อขาย NPC | ราคาเสนอ การยอมรับราคา ส่วนลด การจับได้ว่าเป็นของปลอม และความไว้ใจ | ต้องตรวจเงิน พลัง เจ้าของ และสินค้ายังว่างก่อนสำเร็จ |
| ซื้อขายผู้เล่น | เปิดเสนอขาย ยื่นข้อเสนอ รับ/ปฏิเสธ แลกสินค้า และส่วนลดให้ผู้ซื้อ | การซื้อขายทั่วไปยังมีการยอมรับข้อเสนอ; กฎ “ห้ามปฏิเสธ” ใช้กับการขโมย |
| ของที่ถือและกดใช้ | Passive ขณะถือ ผลกดใช้ ผลดี/ผลเสีย และของใช้แล้วหมด | กฎเดิม: passive นับสูงสุด 5 ชิ้นต่อ kind; โบนัสใช้ชนิดเดิมไม่บวกซ้ำ ต่างชนิดบวกได้ |
| สำเนา | สำเนามีพลังตัวเลข 40% ของฐานก่อนรวมกับตัวคูณที่เกี่ยวข้อง | เก็บเศษตัวเลขจนถึงจุดจ่ายทรัพยากร แล้วใช้กฎปัดที่ตกลง |
| Rarity | ระดับสินค้า ตัวคูณมูลค่า ตัวคูณผลดีตัวเลข และภาพจากต้นแบบเดียว | เป็นคนละแกนกับความแท้และคำสาป; ห้ามสร้างภาพใหม่แยกทุก tier |
| ความไว้ใจ | ความไว้ใจแยกตามพ่อค้า ส่งผลต่อความสามารถและโบนัสสินค้าในร้าน | ต้องระบุว่านับความไว้ใจจริงหรือโบนัสชั่วคราวเมื่อคิดคะแนน |
| ความสามารถพ่อค้า | ปลดล็อกที่ความไว้ใจ 1/3/6 มีเวลารอและการเลือกเป้าหมาย | มีข้อจำกัดร่วมต่อ encounter; ชุดตัวเลือกค้างต้องไม่สุ่มใหม่ด้วยการเปิดปิด |
| ประตู | เลือกพ่อค้า เปลี่ยนประตู ประตูถูกปิดจากเหตุการณ์ | การเปิดประตูด้วย effect ต้องไม่ล้างโทษแบนการค้าโดยปริยาย |
| ตลาดมืด | รายการรับซื้อ เงื่อนไขสินค้า งบ และการจัดการของค้าง | การขายต้องผ่านเงื่อนไขจริงและงบจ่าย |
| ประมูล | ล็อตสินค้า ราคาเสนอและการตัดสินผู้ชนะ | Effect คืนเงินต้องระบุแหล่งเงินและไม่ลดเงินผู้ขายโดยพลการ |
| ขโมย | ขโมยพ่อค้าและผู้เล่นผ่านดวลค้อน/กระดาษ/กรรไกรใน secure economy | กฎล่าสุดเรื่องบังคับเข้าร่วมอยู่ในหัวข้อ 4 |
| อาชญากรรม | ประวัติขโมย การระงับการค้า คูลดาวน์รายเหยื่อ ค่าชดเชย และล้างประวัติ | ผลลดโทษไม่ควรเปลี่ยนสิทธิ์ผู้เสียหายโดยไม่ประกาศกฎใหม่ |
| ตราบาป | ตราระบุคนขโมย โอน/เสนอแลกได้ ใช้ตราคนเดียวกัน 2 ใบเพื่อยึดของตามชุดตัวเลือกปกปิด | ห้ามส่ง item ID ของทรัพย์สินลับทั้งกระเป๋าให้อีกฝ่ายเลือกตรง ๆ |
| Vault | ฝาก/ถอนเงินและสินค้า ขยายช่อง เงินฝากแยกจากเงินใช้จ่าย | ของใน vault ปลอดภัยจากขโมย แต่ใช้และให้ passive ขณะฝากไม่ได้ |
| เงินกู้ | ผู้กู้/ผู้ให้กู้ เงินต้น ผ่อนคืน หลักประกัน กำหนดคืน และการยึดเมื่อผิดนัด | ของค้ำอยู่ escrow ใช้และให้ effect ไม่ได้; ข้อตกลงข้อความไม่ได้บังคับกติกาเพิ่มเอง |
| คำขอซื้อของจาก NPC | NPC อยากรับซื้อสินค้า ผู้เล่นส่งของตามคำขอ มีราคากับการต่อรอง | เป็นระบบเดิมใน wishlist.ts ไม่ใช่ Collector Wishlist ใหม่ |
| สัญญาส่วนตัว NPC | เช่น สัญญาเลือด Vampire และให้ Alien ยืมของแล้วรับคืนพร้อมผลตอบแทน | ต้องติดตามเจ้าของและกำหนดคืน ไม่แจกผลซ้ำเมื่อกลับเข้าหน้า |
| พลังและชีวิต | ใช้พลังกับ action ฟื้นพลัง/ชีวิต จำกัดค่าสูงสุด ความเสียหายและการตาย | การฟื้นและการลดความเสียหายเป็นคนละเหตุการณ์ |
| เศษชีพจร | ซื้อขายระหว่างผู้เล่น คู่ค้า ความต่อเนื่อง/ความระแวง และเศษที่ใช้ฟื้นชีวิต | ต้องรักษากฎป้องกันปั๊มผลตอบแทนกับคู่ค้าเดิม |
| เหตุการณ์และสถานะ | ทางเลือก ค่าใช้จ่าย ผลดี/เสีย จำนวนชาร์จ ระยะเวลา และภัย Dread | ทุกผลควรมีต้นทางและจังหวะหมดอายุชัดเจน |
| รางวัลท้ายช่วง | รับเงินหรือเสี่ยงทายเหรียญ มีโอกาสชนะ ยอดเดิมพัน และผลแพ้/ชนะ | ห้ามรับเงินหรือส่งคำทายซ้ำด้วยคำสั่งซ้ำ |
| Collector ตอนจบ | รวมเงินและมูลค่าสินค้า พร้อมตัวปรับคะแนน | คะแนนพิเศษใหม่ต้องแยกจากคะแนนฐานและเก็บ snapshot ก่อนโอนของจบเกม |
| บันทึกเหตุการณ์ | คำสั่ง ผลลัพธ์ การเคลื่อนเงิน/สินค้า และเหตุผล | ต้องอธิบายว่าเสียพลัง/ชีวิตเพราะอะไร เลือกอะไร และได้ของจากไหน |

## 4. ขโมย: บังคับเป่ายิ้งฉุบและห้ามปฏิเสธ

### กฎที่ยืนยันล่าสุด

1. ผู้เล่นสามารถขโมยได้ตามเงื่อนไขที่ระบบอนุญาต ทั้งเป้าหมายพ่อค้าและผู้เล่น
2. เมื่อเริ่มขโมยอย่างถูกกฎ ระบบเปิดการดวล **เป่ายิ้งฉุบแบบบังคับ ปฏิเสธไม่ได้**
3. ผู้ถูกขโมยไม่มีปุ่มปฏิเสธ ไม่มีการขออนุญาตก่อนดวล และไม่สามารถปฏิเสธการเข้าร่วม
4. การปิดหน้าต่าง เปลี่ยนเมนู หรือหลีกเลี่ยงการส่งมือ ต้องไม่กลายเป็นช่องทางยกเลิกการดวลได้อย่างปลอดภัย
5. ผู้ชนะ/แพ้ต้องถูกตัดสินตามการดวล แล้วจึงใช้ผลขโมยหรือผลลงโทษตามกติกา

“ห้ามปฏิเสธ” ไม่ได้แปลว่าการขโมยทุกคำขอต้องผ่าน: ยังต้องตรวจเป้าหมายมีสิทธิ์ถูกขโมย สินค้าไม่ได้อยู่ vault/escrow ผู้เล่นยังทำ action ได้ ไม่มีดวลค้าง และข้อจำกัดรอบ/คูลดาวน์ที่ใช้จริง

### โครง logic สำหรับพัฒนา

`ตรวจสิทธิ์ → ล็อกเป้าหมายดวล → หักต้นทุนครั้งเดียว → บังคับทั้งสองฝ่ายส่งมือ → ตัดสิน → ย้ายของหรือคิดโทษ → บันทึก → ปิดดวล`

- เก็บมือของแต่ละฝ่ายเป็นความลับจนถึงจังหวะเปิดผล
- เปลี่ยนมือหลังส่งไม่ได้
- เสมอใช้กฎเสมอ/สถานะที่ประกาศไว้ ไม่อ้างว่าเป็นชัยชนะโดยไม่มีที่มา
- การยกเลิกเพราะเป้าหมายใช้ไม่ได้จริงเป็นเรื่องความถูกต้องของ state ต้องแยกจากการปฏิเสธเข้าร่วม

### ต่างจากโค้ดปัจจุบัน

โค้ดมี RPS และข้อจำกัดระหว่างดวลอยู่แล้ว แต่ `expireTheftDuel` ยกเลิกดวลเมื่อหมดเวลา โดยครั้งขโมยและพลังยังถูกใช้ ไม่มีโทษผลแพ้ ส่วนทาง `theft-timeout` ใน engine มีทางยกเลิกด้วย จึงยังไม่ตรงข้อกำหนด “ห้ามปฏิเสธ” แบบครบวงจร

### ยังไม่ตกลง

- หมดเวลา/หลุดเกมให้สุ่มมือ ส่งมือแทน หรือแพ้โดยขาดนัด; ใครรับผลหากทั้งคู่ไม่ส่ง
- ระยะเวลาส่งมือและเวลาต่อรอบเสมอ
- เมื่อเป้าหมายตายหรือสินค้าเปลี่ยนสิทธิ์จากเหตุการณ์ภายนอก จะคืนต้นทุนหรือไม่
- Effect ป้องกันขโมยในคลังเป็นข้อเสนอเก่า ต้องทบทวนให้เป็นผลหลังเข้าร่วมดวล หรือความได้เปรียบที่ประกาศชัด ห้ามแปลเป็นปุ่มปฏิเสธ/ข้ามดวล

ผลแพ้ PvP ที่พบในโค้ดเดิม: เหยื่อได้ตราบาป มีคูลดาวน์รายเหยื่อ และหากมีราคาธุรกรรมอ้างอิง จะเก็บค่าชดเชยเป็นงวดตาม config กฎล่าสุดไม่ได้ระบุแก้จำนวนเหล่านี้ จึงไม่กำหนดตัวเลขใหม่ในเอกสารนี้

## 5. เงินฝาก: ดอกเบี้ย 10% จากเงินก้อนเดิมที่อยู่ข้ามช่วง

### กฎที่ยืนยันล่าสุด

- ดอกเบี้ยฐาน **10%**
- เงินต้องฝากอยู่ข้ามช่วงตามรอบรับดอกเบี้ย จึงมีสิทธิ์
- เงินที่ถอนออกก่อนครบช่วงไม่มีสิทธิ์รับดอกเบี้ยสำหรับช่วงนั้น
- เงินที่เพิ่งเติมไม่รับดอกเบี้ยย้อนหลังหรือทันทีตามยอดรวมใหม่
- ถอนแล้วฝากกลับเป็นเงินฝากใหม่ ไม่คืนอายุของเงินก้อนเดิม
- คิดจาก **เงินต้นที่ยังมีสิทธิ์** ไม่ใช่ยอดคงเหลือสุดท้ายอย่างเดียว

### ตัวอย่างที่กฎต้องรองรับ

| เหตุการณ์ก่อนจ่ายดอกเบี้ย | เงินต้นที่มีสิทธิ์ | ผลตามกฎ 10% |
|---|---:|---:|
| ฝาก 100 แล้วอยู่ครบช่วงโดยไม่ถอน | 100 | ได้ 10 |
| ฝาก 100 แล้วถอนหมดก่อนครบช่วง | 0 | ได้ 0 |

| ถอนเงินเดิม 100 หมด แล้วฝากกลับ 100 ก่อนจ่าย | 0 สำหรับรอบเดิม | ได้ 0 ในรอบเดิม |
| ฝากใหม่ 50 หลังจ่ายดอกเบี้ยรอบหนึ่ง | ยังไม่ครบอายุ | รอให้ครบช่วงของเงินก้อนนี้ก่อน |

### ข้อมูลที่ต้องติดตาม

การเก็บเพียง `vault.credits` ไม่พอ ต้องรู้เงินต้นที่มีสิทธิ์ จังหวะฝาก/ถอน อายุหรือรอบครบกำหนด และรายการจ่ายที่ทำไปแล้ว วิธีทำอาจเก็บเงินฝากเป็นแต่ละก้อนหรือ snapshot พร้อมติดตามยอดที่ถอน ทั้งสองแบบต้องให้ผลตามตัวอย่างข้างบนเหมือนกัน

แนวคิด: `ดอกเบี้ยรอบนี้ = เงินต้นที่ผ่านเงื่อนไขรอบนี้ × 10%` แล้วใช้กฎปัดเศษ/แหล่งเงินที่ตกลงภายหลัง

หากเก็บเป็นก้อน แต่ละก้อนต้องมีจำนวนเงินที่เหลือ จังหวะฝาก และจังหวะแรกที่มีสิทธิ์ เมื่อถอนต้องหักสิทธิ์จากก้อนที่ถูกถอน และป้องกันการจ่ายซ้ำเมื่อ reconnect หรือประมวลผลคำสั่งซ้ำ

### ยืนยันเพิ่มและ runtime ใหม่ 2026-10-28

- ผู้ใช้ยืนยัน: ต้องอยู่ตั้งแต่เริ่มจนจบช่วง ปัดเศษลง ถอนเงินใหม่ก่อนเงินเก่า
- `vaultInterestRules:1` ในรันใหม่: เก็บ snapshot เงินต้นมีสิทธิ์และช่วงล่าสุดใน `PersonalVault.interest` เงินที่ฝากใน REVEAL ช่วง 1 เริ่มนับเมื่อเริ่มช่วง 2 แล้วรับตอนเริ่มช่วง 3 หากยังอยู่ครบ
- เติมใหม่ไม่เพิ่ม snapshot ถอนจนต่ำกว่าเงินต้นเดิมจะลดสิทธิ์ ถอนแล้วฝากกลับไม่คืนสิทธิ์
- จ่ายเข้ากระเป๋าตามงบธนาคารเดิม ไม่ทบต้นเอง ป้องกันจ่ายซ้ำแม้งบไม่พอจ่ายเต็มในครั้งแรก
- Audit ที่ไม่มี flag เก็บ 4% จากยอดรวมตามเดิม ไม่ตีความประวัติใหม่; ยอดไร้อายุในรันกติกาใหม่เริ่มนับใหม่ ไม่รับย้อนหลัง
- โบนัส/เพดานจาก effect ยังเป็นข้อเสนอ ไม่ได้เพิ่มในงานนี้

## 6. Collector Wishlist: ขอ 3 + สุ่ม 2, รอ 2 turn, เลือกจาก 5 ช่องปกปิด

### กฎที่ยืนยันล่าสุด

1. ทุก **2 turn** มีจังหวะ Wishlist กับ Collector
2. ผู้เล่นเลือกสินค้าที่อยากได้ **3 อย่าง**
3. Collector นำสินค้ามาในอีก **2 turn** หลังส่ง Wishlist
4. ชุดเสนอประกอบด้วยของที่เลือก **3 อย่าง** และของที่ระบบสุ่มเพิ่ม **2 อย่าง** รวม **5 อย่าง**
5. ผู้เล่นเห็นตัวเลือกแบบปกปิด ไม่รู้ว่าช่องที่เลือกคือสินค้าอะไร
6. เปิดดูได้ **1 อย่าง** ของชุดนั้น
7. ของเป็น **สินค้าให้ซื้อ** ไม่ได้แจกฟรี ผู้เล่นต้องมีเงินซื้อชิ้นที่เลือก

ต้องสับตำแหน่งทั้ง 5 ช่อง ไม่แสดงว่า “สามช่องแรกคือของที่ขอ” หรือส่ง mapping ลับไปให้ client ผู้เล่นจำชื่อ 3 อย่างที่เคยขอได้ แต่ไม่รู้ตำแหน่งในชุดปกปิด

### ตัวอย่างตารางเวลา — ข้อเสนอจังหวะเริ่ม

| Turn | กิจกรรม |
|---:|---|
| 2 | ส่ง Wishlist ชุด A: เลือก 3 อย่าง |
| 3 | ชุด A อยู่ระหว่างรอ |
| 4 | Collector นำชุด A มาขายเป็น 5 ช่อง; ส่ง Wishlist ชุด B ได้ตามรอบ |
| 6 | นำชุด B มาขาย; ส่งชุด C |
| 8 | นำชุด C มาขาย; ส่งชุด D |

ทุก 2 turn และการรออีก 2 turn เป็นกฎยืนยัน ส่วนการเริ่มที่ turn 2 รวมถึงลำดับ “รับชุดเก่าก่อนส่งชุดใหม่” เป็นตัวอย่างที่เสนอ ยังต้องยืนยัน

### ข้อมูลและลำดับธุรกรรมที่ต้องมี

- Wishlist: เจ้าของ ชุดที่เลือก เวลาส่ง กำหนดส่ง สถานะ และ ID ชุด
- Delivery: สินค้าทั้ง 5 instance ราคาจริง mapping ตำแหน่งลับ จำนวนสิทธิ์เปิดดูที่ใช้ และสถานะซื้อ/ปิดชุด
- เก็บตำแหน่งและราคาไว้เมื่อสร้างชุด ไม่สุ่มใหม่ทุกครั้งที่เปิดเมนูหรือ reconnect
- ใช้สิทธิ์เปิดดูหนึ่งครั้งต่อชุดใน server ไม่ใช่ตัวนับเฉพาะหน้าจอ
- ก่อนยืนยันซื้อ ตรวจว่าเงินใช้จ่ายพอ ของยังซื้อได้ และยังไม่ถูกซื้อไป จากนั้นหักเงินและย้ายของพร้อมกัน
- คำสั่งเดิมส่งซ้ำต้องไม่เปิดเพิ่ม หักเงินซ้ำ หรือได้สินค้าซ้ำ
- เงินใน vault ต้องไม่ถูกนำมานับเป็นเงินใช้จ่ายโดยอัตโนมัติหากยังไม่ได้ถอนตามกฎ
- บันทึกเหตุผลการได้สินค้าเป็น “ซื้อจาก Collector ชุด X” พร้อมราคาและ Wishlist ต้นทาง ไม่ใช่ได้รับฟรี

### ข้อเปิดเดิม — ปิดด้วยสเปกทดลองที่อนุมัติ2026-11-02

- 3 อย่างที่ขอต้องต่าง kind กันหรือเลือกซ้ำได้; สุ่มเพิ่ม 2 อย่างซ้ำกับ Wishlist/กันเองได้หรือไม่
- เลือก kind เท่านั้น หรือเลือก rarity/ความแท้/คำสาปได้ด้วย
- ราคาเปิดเผยตั้งแต่เห็นหลังการ์ดหรือเมื่อเปิดดู; การแสดงราคาห้ามรั่วชื่อสินค้าโดยไม่ได้ตั้งใจ
- การเปิดดูต้องมีเงินพอซื้อชิ้นนั้นตั้งแต่ตอนเปิดหรือเช็กเฉพาะยืนยันซื้อ
- เปิดดูหนึ่งช่องแล้วซื้ออีกช่องได้หรือไม่; การกดเลือกช่องถือว่ายืนยันซื้อทันทีหรือไม่
- ซื้อได้หนึ่งชิ้นหรือหลายชิ้นจาก 5; ข้ามการซื้อได้หรือไม่; ชุดหมดอายุเมื่อใด
- ปฏิเสธ/เงินไม่พอแล้วรักษาสิทธิ์เปิดดูหรือสถานะชุดอย่างไร
- ส่ง Wishlist ไม่ทันให้ข้ามรอบหรือเลือกแทน; ตาย/จบเกมก่อนส่งของทำอย่างไร
- แต่ละผู้เล่นมีชุดส่วนตัวหรือชุดร่วม ต้องยืนยันก่อนกำหนดการแข่งขันแย่งซื้อ

### แยกจากระบบเดิม

ระบบใน `wishlist.ts` คือ NPC ขอรับซื้อของจากผู้เล่น มีราคาและการต่อรอง ส่วนระบบใหม่คือผู้เล่นขอซื้อของจาก Collector ภายหลัง จึงไม่ควรใช้ชื่อ action/สถานะเดียวกันจนสับสน

Collector ตอนจบยังเป็นอีกหน้าที่หนึ่ง การส่งของรอบ Wishlist ไม่ได้แปลว่าจบเกมหรือเก็บทรัพย์สินไปคิดคะแนนทันที

## 8. ข้อจำกัดร่วมของ effect

1. คลัง 75 แนวเป็นข้อเสนอ ไม่ใช่รายการที่อนุมัติหรือทำงานครบแล้ว
2. กฎบังคับเป่ายิ้งฉุบอยู่เหนือข้อเสนอป้องกันขโมย ห้ามใช้ effect เพื่อปฏิเสธหรือทำให้คู่แข่งเสีย action โดยไม่มีดวล
3. โบนัสดอกเบี้ยใช้เฉพาะเงินต้นที่ผ่านอายุฝาก ห้ามทำเงินเติมใหม่ได้รับทันที
4. Collector Wishlist ต้องยังจ่ายเงินจริง สิทธิ์ดูเพิ่ม/แจกฟรี/เร่งส่ง/เพิ่มจำนวนช่องเป็นการแก้กฎใหม่ ต้องตกลงแยก
5. Effect ไม่เพิ่มคะแนนพิเศษหรือสถิติสำเร็จโดยตรงหากยังไม่มีการอนุมัติวิธีนับ
6. กฎสัญญาและค่าชดเชยของอีกฝ่ายต้องได้รับการคุ้มครอง ส่วนลดของผู้จ่ายต้องระบุว่าใครรับภาระส่วนต่าง
7. ระบุ trigger เป้าหมาย ต้นทุน ระยะเวลา การสะสม เพดาน แหล่งเงิน และการหมดสิทธิ์ทุก effect ก่อนพัฒนา
8. ค่าที่เป็นสิทธิ์หนึ่งครั้ง ช่องเก็บของ จำนวนตัวเลือก หรือการเปลี่ยนเวลา ต้อง tune แยกจากโบนัสราคา/เปอร์เซ็นต์
