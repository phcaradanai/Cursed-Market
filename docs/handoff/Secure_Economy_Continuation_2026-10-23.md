วันที่: 2026-10-23 — Asia/Bangkok
Repository: `/Users/Projects/Cursed Market`
ภาษาในการคุยกับผู้ใช้: ไทย กระชับ ตาม caveman skill

## 1. เป้าหมายสำหรับ agent ที่รับงานต่อ

ต่อยอดระบบ secure economy ที่มีอยู่แล้วด้วยกติกาที่ผู้ใช้ยืนยันในบทสนทนาล่าสุด:

1. โทษขโมยผู้เล่นแพ้: cooldown เฉพาะเหยื่อเดิม, ตราคนบาป, ค่าชดเชยสี่ช่วง
2. ซื้อขายและใช้ตราคนบาป
3. ใบประกาศอาชญากรล้างหลายคดี
4. ดอกเบี้ยเงินฝาก vault 4% ต่อช่วง แบบไม่มีเพดาน

ไฟล์นี้เป็นข้อกำหนดส่งต่องาน ยังไม่ได้ลงโค้ดกติกาใหม่ในรอบเขียน handoff นี้
ให้ทำงานส่วนที่ชัดเจนต่อได้ และถามเฉพาะรายละเอียดที่มีผลต่อพฤติกรรมแต่ยังไม่ตกลง
ไม่ต้องถามซ้ำเรื่องอัตรา 4%, การไม่มีเพดาน, การใช้ตราสองใบ หรือสูตรใบประกาศ
ห้ามเปลี่ยนข้อเสนอที่ยังไม่ยืนยันให้กลายเป็นกฎโดยไม่แจ้งผู้ใช้

**ลำดับอำนาจของเอกสาร:** ข้อกำหนดที่ยืนยันในไฟล์นี้ใหม่กว่าส่วน “Explicitly deferred”
ใน `docs/plan/Secure_Economy_v0.5.md` และ `docs/validation/Secure_Economy_v0.5.md`
สองไฟล์นั้นอธิบายชุดที่ลงโค้ดและตรวจไว้ก่อนการคุยรอบล่าสุด ไม่ใช่หลักฐานว่ากฎใหม่เสร็จแล้ว

## 2. สถานะงานปัจจุบัน

| ระบบ | มีอยู่แล้ว | ต้องทำต่อ |
| --- | --- | --- |
| Theft | sealed RPS ขโมยพ่อค้า/ผู้เล่น, จ่าย 1 พลัง, ครั้งเดียวต่อ encounter, เสมอเล่นใหม่ฟรี | โทษแพ้ PvP ตามหัวข้อ 3–5 |
| Merchant penalty | trust พ่อค้าคนนั้น −2, สะสมช่วงห้ามค้าพ่อค้าทั้งหมด | รักษาพฤติกรรมเดิม |
| Criminal notice | ล้างคดีเดียวที่ราคา 2 × storefront ask | รองรับทุกคดีด้วยสูตรรวม |
| Personal vault | ฝากของ/เงินหลังรับเงินท้ายช่วง, 2 ช่องฟรี, เพิ่มช่อง 10/15/20/25… | ดอกเบี้ย 4% ไม่มีเพดาน |
| Player loans | ตกลงสองฝ่าย, ย้ายเงินจริง, escrow หลักประกัน, ผ่อนและยึดตามกำหนด | รักษาพฤติกรรมเดิมและข้อยกเว้นหลักประกัน |
| Price integrity | immutable item base, audit ราคาปั่น, reappraisal, liquidation limits | รักษากลไกและข้อมูลราคาเดิม |
| Sinner seals | ยังไม่มีในเส้นทาง PvP ที่ตรวจอ่าน | เพิ่ม ownership, trade, redemption, views และ UI |

ตรวจโค้ดต้นทางในวันเขียนไฟล์: `chooseTheftHand` กรณีแพ้ PvP ยังเขียนเพียง note;
`clearCrime` ยังปฏิเสธกรณี `cases.length !== 1`; storage ยังไม่มีการจ่ายดอกเบี้ย

## 3. กฎที่ยืนยัน: แพ้การขโมยผู้เล่น

- ห้ามขโมย **ผู้เล่นที่เป็นเหยื่อคนเดิม** อีก **2 encounter ถัดไป** ไม่ใช่ห้ามขโมยทุกคน
- ตัวอย่าง แพ้ช่วง N: ขโมยคนเดิมไม่ได้ใน N+1 และ N+2; กลับมาขโมยได้ใน N+3
- โอกาสขโมยหนึ่งครั้งใน encounter ปัจจุบันยังใช้ไปตามระบบเดิม
- เหยื่อได้รับ **ตราคนบาป 1 ตรา** ที่ระบุผู้ขโมยคนนั้น เมื่อผู้ขโมยแพ้
- มีค่าชดเชยตามหัวข้อ 5 แยกจากตราและ cooldown
- กฎนี้ใช้เมื่อแพ้ PvP ไม่เพิ่มโทษให้ draw หรือการยกเลิก duel โดยปริยาย
- โทษ PvP แยกจากโทษพ่อค้า ใบประกาศพ่อค้าไม่ล้างตรา, cooldown หรือภาระชดเชยนี้

## 4. กฎที่ยืนยัน: ตราคนบาป

### Ownership และการใช้สิทธิ์

- แต่ละตราต้องระบุว่าเป็นตราของผู้ขโมยคนใด และใครเป็นผู้ถือปัจจุบัน
- ผู้ถือคนใดก็ได้ที่มี **2 ตราของผู้ขโมยคนเดียวกัน** ใช้สิทธิ์ได้
  ไม่จำเป็นต้องเป็นเหยื่อเดิม และรวมตราที่ซื้อจากคนอื่นได้
- สุ่มของของผู้ขโมยมา **3 ชิ้นแบบปิดบัง** ให้ผู้ถือเลือกเอา **1 ชิ้น**
- ผู้เลือกไม่รู้ว่าของแต่ละใบคืออะไร ก่อนเลือกสำเร็จ
- ใช้แล้ว **ตราทั้งสองถูกใช้หมด** ห้ามใช้ซ้ำ
- เลือกจากของติดตัวเท่านั้น **ไม่รวมของใน personal vault และของที่ค้ำประกัน**
- ไม่ได้ตกลงให้การใช้ตราต้องเป่ายิ้งฉุบเพิ่ม หรือเสียค่าใช้สิทธิ์เพิ่มเติม

ตัวอย่าง: A ขโมย B และ C แล้วแพ้ ทั้งสองได้ตราชื่อ A คนละใบ
หาก B ซื้อตราจาก C จะมี 2 ตราชื่อ A และใช้สิทธิ์กับของติดตัว A ได้

### ซื้อขายตรา

- ตราซื้อขายได้ ผู้ถือกำหนดราคาต่อรองได้ตามใจ
- สิ่งตอบแทนอาจเป็น **เครดิต, พลัง, ชีวิต, สินค้า หรือข้อตกลงผสม**
- เป็นการซื้อขายโดยตกลงกัน ไม่ใช่บังคับผู้ซื้อให้รับราคาที่เสนอ
- ผู้ขโมยสามารถซื้อคืนตราที่เป็นชื่อตัวเอง เพื่อลดความเสี่ยงที่คนอื่นจะรวมครบสองตรา
- ข้อตกลงที่เป็น free text ต้องไม่กลายเป็นการรันคำสั่งเกมโดยอัตโนมัติ

รายละเอียดการทำลายตราที่ซื้อคืน, ขอบเขตการโอนชีวิต/พลัง และกรณีของไม่ถึงสามชิ้น
ยังไม่ยืนยัน ดูหัวข้อ 8 อย่าเติมกฎเหล่านี้เงียบ ๆ

## 5. กฎที่ยืนยัน: ค่าชดเชยแพ้ PvP

**กฎล่าสุดคือ 5% ต่อครั้ง บังคับเก็บ 4 ครั้ง ตอนเริ่ม 4 encounter ถัดไป**

- ผู้ขโมยเป็นผู้จ่าย เหยื่อเป็นผู้รับ
- ฐานอ้างอิงคือ **ราคาซื้อขายล่าสุดของสินค้าที่พยายามขโมย**
  ไม่ใช่ราคาหน้าร้านที่ใช้คำนวณใบประกาศพ่อค้า
- ไม่มีค่าชดเชย 2% ทันทีแบบเดิมอีกแล้ว
- ไม่คิดค่าชดเชยเมื่อขโมยสำเร็จ
- หักตอน **เริ่ม encounter** ไม่ใช่ทุกครั้งที่เปลี่ยน phase ย่อย
  `PORTALS → APPRAISAL → TRADE → REVEAL` ไม่ใช่สี่งวด
- **ห้ามใช้เครดิตใน vault** สำหรับการบังคับเก็บนี้
- หากราคาอ้างอิงคงที่ แต่ละครั้งคิด 5% รวมสี่ครั้งเท่ากับ 20%

ตัวอย่าง: ขโมยของราคา 100 แล้วแพ้ใน encounter 3

| ตอนเริ่ม encounter | ค่าชดเชย |
| --- | ---: |
| 4 | 5 |
| 5 | 5 |
| 6 | 5 |
| 7 | 5 |
| รวม | 20 |

**ยังไม่ยืนยัน:** ผู้ช่วยแนะนำให้ snapshot ราคาตอนแพ้ เพื่อยอดไม่เปลี่ยนตามการขายต่อ
ผู้ใช้ยังไม่ได้ตอบรับรายละเอียดนี้โดยตรง รวมถึงการปัดเศษและเงินไม่พอ
อย่านำตัวอย่างราคา 100 ไปอ้างว่าผู้ใช้อนุมัติวิธีจัดการเศษเครดิตแล้ว

## 6. กฎที่ยืนยัน: ใบประกาศล้างหลายคดี

ผู้ใช้ตอบรับข้อเสนอเดิมทั้งหมดสำหรับใบประกาศ:

```text
noticePrice = 2 × sum(originalStorefrontAsk ของทุกคดีที่ยังไม่ล้าง)
```

- บันทึกราคาหน้าร้าน ณ ตอนเกิดแต่ละคดี การประเมินใหม่/ขายต่อไม่เปลี่ยนค่าล้าง
- ขโมยพลาดซ้ำกับของชิ้นเดิมนับเพิ่มอีกคดี
- ห้ามใช้คดีที่ถูกที่สุดหรือคดีล่าสุดล้างทุกคดี
- ไม่มีตัวคูณจำนวนคดีเพิ่มอีกชั้น
- โทษห้ามค้าขายหมดแล้ว ประวัติยังอยู่จนซื้อใบประกาศ
- จ่ายเต็มแล้วล้างทุกคดีและยกเลิกโทษห้ามค้าขายทันที **ไม่คืน trust ที่เสียไป**
- รักษาการซื้อใบประกาศได้แม้ Dark Market ปกติไม่เปิด
- ไม่ล้างตราคนบาป, cooldown PvP หรือค่าชดเชยระหว่างผู้เล่น

ตัวอย่าง: คดีราคา 20, 30, 50 ต้องจ่าย `2 × (20 + 30 + 50) = 200` เครดิต

## 7. กฎที่ยืนยัน: ดอกเบี้ย vault

- **4% ต่อ encounter**
- **ไม่มีเพดาน** คำนวณจากยอดเงินฝากทั้งหมด
- ยกเลิกทั้งอัตรา 2% และเพดาน 2 เครดิตที่ผู้ช่วยเคยเสนอ
- เงินฝากที่เข้าเกณฑ์ 100 ให้ดอกเบี้ย 4; เงินฝาก 1,000 ให้ดอกเบี้ย 40 ต่อช่วง
- เป็นดอกเบี้ยของเงินฝาก ไม่ใช่เพิ่ม held effect ให้ของที่ฝาก
- ห้ามลดอัตรา เพิ่มเพดาน หรือคิดเฉพาะเงินฝากบางส่วนเพื่อบาลานซ์โดยไม่ถามผู้ใช้

**ยังไม่ยืนยัน:** จ่ายตอนไหน, ฝากนานเท่าใดจึงได้ดอกเบี้ย,
ดอกเบี้ยเข้ากระเป๋าหรือ vault, ทบต้นหรือไม่ และวิธีสะสมเศษ
ข้อเสนอเดิมของผู้ช่วยว่า “ถือข้ามช่วง, จ่ายเข้ากระเป๋า, ไม่ทบต้นอัตโนมัติ”
ยังไม่ใช่กติกาที่ผู้ใช้ตอบรับ

## 8. เรื่องที่ยังต้องตัดสินใจ แยกจากกฎที่ยืนยัน

ถามแบบรวมสั้น ๆ เมื่อจะทำส่วนที่ขึ้นกับคำตอบ ระหว่างรอให้ทำงานที่ไม่ขึ้นกับคำตอบต่อ

| เรื่อง | ยังไม่ตกลง | ข้อเสนอ/ข้อควรพิจารณาที่ไม่ใช่คำอนุมัติ |
| --- | --- | --- |
| ราคาอ้างอิงค่าชดเชย | snapshot ตอนแพ้ หรือเปลี่ยนตามราคาภายหลัง | แนะนำ snapshot เพื่อยอดคงที่ |
| เศษเครดิต | การปัด 5% และ 4%; เก็บเศษข้ามงวดหรือไม่ | สถานะเงินปัจจุบันตรวจว่าเป็น integer อย่าใส่ float ตรง ๆ |
| เงินชดเชยไม่พอ | หักบางส่วน/ติดหนี้/งวดสูญ/เลื่อนงวด | ห้ามดึง vault หรือสร้างหนี้เองโดยถือว่าอนุมัติ |
| ไม่มีราคาซื้อขาย | ใช้ราคาใด เมื่อเป็นของจากเหตุการณ์/ของฟรี/แลกของ | อย่าเปลี่ยนไปใช้ base ลับโดยไม่กำหนดกติกา |
| หลายภาระชดเชย | ซ้อนกันได้อย่างไรและลำดับหักเมื่อเงินไม่พอ | แต่ละเหยื่อและแต่ละคดีต้องแยกแยะได้ |
| ตาย/จบ run | ค่าชดเชยและดอกเบี้ยที่เหลือทำอย่างไร | ไม่เร่งกำหนดหรือยกหนี้ให้เอง |
| ลำดับเริ่มช่วง | หักชดเชยก่อน/หลังดอกเบี้ยและผลอื่น | มีผลต่อเงินติดตัวและการหลบการจ่าย |
| ตราซื้อคืนชื่อตัวเอง | ทำลายทันที หรือเก็บไว้ | ผู้ช่วยเสนอทำลายทันที ยังไม่ยืนยัน |
| ของยึดไม่ถึงสามชิ้น | เลือกเท่าที่มีหรือรอครบสาม | ผู้ช่วยเสนอเลือกเท่าที่มี ยังไม่ยืนยัน |
| ไม่มีของยึดได้ | ใช้สิทธิ์ไม่ได้/เก็บสิทธิ์/ผลอื่น | ผู้ช่วยเสนอเก็บตราไว้ไม่ใช้หมด ยังไม่ยืนยัน |
| ชุดเลือกปิดบัง | สุ่มตอนไหน, ล็อกอย่างไร, ยกเลิก/หมดเวลาอย่างไร | ผู้ช่วยเสนอชุดเดิมเมื่อ reconnect และใช้ตราเมื่อรับของสำเร็จ |
| สถานะของที่ยึด | การจัดการ stolen flag/ของล็อก/รายการขาย | รักษาข้อห้าม custody เดิม; อย่าเพิ่มโทษการฟอกของเอง |
| ตราในระบบอื่น | ฝาก/ขโมยตราได้ไหม; มีวันหมดอายุไหม | ยังไม่ได้กำหนดให้ตราเป็นสินค้าแบบ catalog |
| แลกพลัง/ชีวิต | ขีดจำกัด, จ่ายจนตายได้ไหม, เกิน max ผู้รับทำอย่างไร | ไม่สร้างทรัพยากรหรือทิ้งมูลค่าโดยไม่แจ้ง |
| ดอกเบี้ย | ระยะถือครอง, เวลาจ่าย, ปลายทาง, ทบต้น | 4% และไม่มีเพดานยืนยันแล้ว อย่าถามซ้ำ |

## 10. ข้อจำกัดทางเทคนิคที่ต้องรักษา

- Server เป็นผู้ตัดสิน, client ส่งคำสั่งเท่านั้น ไม่ยอมรับยอดค่าชดเชย/ดอกเบี้ยจาก client
- คำสั่งซ้ำ request ID เดิมต้องไม่ออกตรา/จ่ายเงิน/ยึดของซ้ำ
- Scheduled charges และดอกเบี้ยต้องเกิดครั้งเดียวต่อ encounter แม้ reconnect หรือ replay
- ข้อมูลของสามใบปิดบังต้องไม่หลุดผ่าน ID, art, alt, tooltip, ราคา, effects หรือ raw WS payload
- RPS มือฝ่ายตรงข้ามและสินค้าที่พยายามขโมยยังต้องปิดบังตามกติกาเดิม
- การแสดงค่าชดเชย 5% ก่อนขโมยอาจเปิดเผยราคาของเป้าหมายที่ซ่อนอยู่ หลีกเลี่ยง price oracle
- แลกตรา/เงิน/ของ/พลัง/ชีวิตต้องตรวจสิทธิ์และชำระพร้อมกัน ไม่เกิดครึ่งธุรกรรม
- ของใน vault/collateral ไม่ถูกยึด ไม่กลับมาให้ held effects และไม่ถูกค้ำซ้ำ
- รักษา wealth/Collector ที่นับทรัพย์สินยังเป็นของผู้เล่น และ ledger custody ที่มีอยู่
- ดอกเบี้ยต้องมีแหล่งบัญชีระบบและ ledger ตามแบบของเกม ไม่เพิ่ม balance ลอย ๆ ให้ invariant พัง
- รักษา RNG แบบ seeded, replay และความเข้ากันได้ historical audits
  `secureEconomy` ปัจจุบันเป็น opt-in ใน fixtures แต่ latest server เปิดใช้อยู่
  การเปลี่ยนพฤติกรรม secureEconomy เดิมอาจต้องระบุ rule version ใหม่ อย่าแค่เปลี่ยน replay เก่า
- ช่วง duel เปิดอยู่ ผู้เข้าร่วมทำได้เฉพาะส่งมือ/ระบบ timeout ตาม lock เดิม
- CSS client import จาก `main.tsx` เพื่อให้ Node SSR tests import component ได้
- UI ใช้หน้าตา dark fantasy เดิม แสดงตาม phase ไม่ทำ redesign หรือใช้ dropdown เพิ่มโดยพลการ

## 12. เกณฑ์รับงานและการทดสอบ

- Fail N: ขโมยเหยื่อเดิมไม่ได้ N+1,N+2; N+3 ได้ ส่วนเหยื่ออื่นไม่โดนห้ามจากกฎนี้
- แพ้ครั้งเดียวออกตราหนึ่งใบให้เหยื่อ; draw/cancel/retry ไม่สร้างตราซ้ำ
- ตราโอนผู้ถือได้ แต่ชื่อผู้ขโมยไม่เปลี่ยน; รวมสองใบจากคนละเหยื่อได้
- ใช้สองใบแล้วเหลือศูนย์ ได้ของเดียว; ไม่มี ownership ซ้ำ/ของหาย/เลือกของลับด้วย guessed ID
- เงิน/พลัง/ชีวิต/ของในการซื้อขายตราเป็นการย้ายตามข้อกำหนดที่ตกลง ไม่สร้างขึ้นใหม่
- ค่าชดเชยราคา 100: หัก 5 ใน N+1…N+4 เท่านั้น รวม 20; ไม่หักใน N, N+5 หรือทุก phase
- ชนะขโมยไม่มีภาระชดเชย; vault credits ไม่ถูกหัก แม้ wallet ไม่พอ
- หลายคดี ask 20/30/50: quote และเงินจริง 200; ไม่คืน trust; ไม่ล้าง PvP obligations
- ดอกเบี้ย eligible 100/1,000 ต้องได้ 4/40 ไม่มี cap 2; ทดสอบ policy timing/เศษหลังตกลง
- ทดสอบ nonparticipant, forged input, stale state, duplicate command, reconnect และ replay
- ทดสอบลำดับเริ่ม encounter, settlement และ cancellation โดยเฉพาะกรณีหมดพลัง/ตาย
- ตรวจ UI desktop/mobile: cooldown, ตรา, เงื่อนไขเทรด, ไพ่ปิดบัง, งวดชดเชย และดอกเบี้ย
- มี Thai/English ครบ และ flow ใหม่ไม่ทำ bot ติดค้าง
