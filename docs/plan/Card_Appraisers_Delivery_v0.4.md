# Cursed Market v0.4 — แผนส่งมอบ Card Appraisers

2026-10-13 — ผู้ใช้ขอวางแผนและตั้ง goal หลังเปรียบเทียบเวลาในการทำสามแนวภาพ แผนนี้ใช้ **Card + realistic art** เป็นแนวทำงานตั้งต้นตามข้อเสนอที่ใช้เวลาน้อยที่สุด ไม่บันทึกว่าเป็นการยืนยันแบรนด์หรือรูปแบบเกมเต็มจากผู้ใช้

## Goal และจุดจบ

ส่งมอบต้นแบบนักประเมินต่างมิติ v0.4 ที่เล่นบน LAN ได้จริง 2–4 คน ตั้งแต่สร้างห้องจนจบ run และ rematch มีหน้าการ์ดภาษาไทย, NPC ที่มีพฤติกรรมต่างกัน, ประตูสุ่ม, credit/พลัง/inventory, การประเมินและต่อรอง, Dark Market, **50 RNG events และ buff/debuff รวม 20 ประเภทที่ทำงานจริง** พร้อม audit/replay และหลักฐานทดสอบ

Goal นี้จบเมื่อระบบครบขอบเขตและพร้อมให้คนทดลอง ไม่ต้องรอให้ผู้ทดสอบพร้อม และไม่ถือว่าการผ่าน goal พิสูจน์ความสนุกหรืออนุมัติลงทุนทำเกมเต็มแล้ว Human playtest เป็นขั้นถัดไปที่เก็บหลักฐานแยกกัน

## ข้อกำหนดที่รักษาไว้

- ผู้เล่นเลือกประตูพบพ่อค้าต่างมิติ ประเมิน ซื้อด้วย credit หรือรับเงื่อนไข และจัดชุดของที่มีทั้งผลดีและผลเสีย
- การกดราคา NPC อาจเสียเงิน เสียของ หรือเสียชีวิต ผลตรวจจับกับผลเสียเป็นคนละการสุ่ม ตัวอย่าง base 20 / ประเมิน 10 / ถูกจำได้ 20% ไม่ใช่ตาย 20%
- ต่อรองกับผู้เล่นไม่มีบทลงโทษ NPC; ผลสินค้าและสัญญาที่มีอยู่ยังทำงาน
- ตายหรือพลังหมดพักเฉพาะ encounter ปัจจุบัน แล้วกลับมาเล่น encounter ถัดไป ผู้พักไม่ทำให้เกมค้าง
- Dark Market ตรวจการสุ่มเปิดก่อนแต่ละ encounter; เมื่อเปิดมีรายการสุ่มตั้งแต่ 1 รายการ และรับซื้อจนจบ encounter นั้น ขายของที่เพิ่งได้มาได้และรับ credit ทันที
- ชนิดสินค้าที่เคยขายยังอยู่ใน pool ของ demand ครั้งถัดไป การสุ่มไม่จงใจเล็ง inventory หรือประวัติขายของใคร
- ใช้คลัง [E01–E50, B01–B10, D01–D10](RNG_Content_v0.4.md) ครบ ไม่ส่งมอบเพียงชื่อรายการหรือผลที่ต่างกันแค่ภาพ
- Server เก็บ seed, base/คำสาปจริง, ผลตรวจส่วนตัว และข้อเสนอในอนาคต Retry/reconnect ไม่ทำให้สุ่มใหม่หรือคิดเงินซ้ำ

## ลำดับงานและเกณฑ์ผ่าน

### M0 — ทำกติกาให้พร้อมเขียนโค้ด

สร้าง decision ledger ของ v0.4 ระบุ phase, action, เจ้าของข้อมูล, จังหวะผลสินค้า/สถานะ, recovery, คะแนน, การตอบสนอง NPC และสูตรตลาด ใช้ค่าทดลองที่แก้ผ่าน rules config ได้ ไม่ต้องถามเรื่องพักหนึ่ง encounter หรือเวลาปิดตลาดซ้ำ

แนวทดลองตั้งต้นจากร่างเดิม: run 3 encounters; แต่ละคนเลือกประตูและพบ NPC ของตนพร้อมกัน ก่อนเปิดช่วงต่อรองร่วมกัน; credit เป็นเงินแยกจากพลัง; เห็นช่วงราคาและเบาะแสก่อนใช้พลังตรวจ; ผู้ตายได้ 0 สำหรับ encounter นั้นโดยไม่ล้างคะแนนก่อนหน้า; การหมดพลังหยุด action โดยไม่ล้างคะแนนที่ได้แล้ว; คืนพลังขั้นต่ำก่อนผลต้น encounter เพื่อให้กลับมาเล่นได้จริง

Dark Market ตั้งต้นใช้โอกาสเปิด 50%, demand สุ่ม 1–3 ชนิดจาก pool ที่เข้าถึงได้, quote คงที่ใน encounter, quota ต่อผู้เล่นและงบที่กันไว้ครบตาม quote ราคาตลาดไม่อิงเลขประเมินที่ผู้เล่นกรอก ตัวเลขทั้งหมดเป็นสมมติฐาน balance ของผู้ช่วย ต้องบันทึกค่าและเหตุผลใน M0 ก่อนใช้จริง

การขอดู NPC ของคนอื่นเป็นการเปิดข้อมูลที่เจ้าของอนุญาตเท่านั้น ไม่ได้ให้สิทธิ์ซื้อแทนโดยอัตโนมัติ การซื้อข้ามร้านต้องมีขั้นยืนยันสิทธิ์จากนักประเมินเดิม และแสดงก่อนซื้อว่าใครรับผล NPC ของที่เพื่อนถือซื้อ/แลกได้เมื่อเจ้าของยอมรับ ข้อมูลตรวจส่วนตัวไม่ติดไปกับการขอดูโดยอัตโนมัติ

**ผ่านเมื่อ:** มีตารางกติกาและตัวอย่างครบสำหรับราคาปกติ/กดราคา, ตรวจของ, ซื้อ/รับเงื่อนไข, พัก/ฟื้น, คะแนน, P2P/cross-shop และตลาดเปิด/ปิด รวมกรณีทุกคนพักพร้อมกัน สูตรและค่าทดลองไม่เหลือพฤติกรรมที่ builder ต้องเดา

### M1 — Rules engine และเส้นทางเล่นครบหนึ่ง run

ใช้ TypeScript kernel, seeded random, private views และ audit ที่มีอยู่ สร้างกติกา appraisal ตาม phase ใหม่ ไม่บังคับให้ผ่าน seller/bid/wager ของ v0.3 เพิ่ม encounter IDs และตัวตรวจสิทธิ์ผู้พัก

เริ่ม fixture 3 NPC / 6 สินค้า / 3 encounters เพื่อพิสูจน์เส้นทาง แล้วขยายพฤติกรรมและชนิดสินค้าจนครอบคลุม NPC/เงื่อนไขที่คลัง event ต้องใช้ ออร์ก, vampire, autometa, alien และ dark one มีข้อเสนอหรือปฏิกิริยาต่างกัน ไม่ต่างเพียงรูป

**ผ่านเมื่อ:** จำลอง run จบและรีเซ็ตได้ การประเมินไม่ได้บังคับซื้อ เงิน/พลังไม่ติดลบ ไม่มีของซ้ำ ผู้พักฟื้นได้ เกิดผลสถานะตามจังหวะ และ replay ตรง state/คะแนน

### M2 — ครบ RNG, สถานะ และ Dark Market

แปลง E01–E50 และ B01–D10 เป็นข้อมูล typed พร้อม resolver ที่ทำงานจริง ตรวจ eligibility, phase, ระยะผล, การใช้ซ้ำ/หมดอายุ และ interaction ตามคลัง Dark Market เป็นระบบสุ่มแยกจาก event slots และไม่เผย demand ล่วงหน้า

**ผ่านเมื่อ:** ทุก event/status มีกรณีทดสอบที่เข้าถึงได้และตรวจผลที่กำหนด ไม่ใช่ตรวจจำนวน ID อย่างเดียว มี forced fixtures สำหรับตลาดปิด/เปิด, quota, expiry, ซื้อแล้วขายทันที, ขายไปก่อนแล้วเกิด demand ภายหลัง, ของล็อก, ผู้พัก, retry และคำสั่งแข่งขันกัน

### M3 — Multiplayer 2–4 คน

นำ private rooms, session/reconnect และการยืนยัน seat กลับมาใช้ เชื่อม protocol/validation กับ phase ใหม่ การจ่ายเงิน โอนของ quota และผลตอบรับต้องสำเร็จครั้งเดียวบน state ล่าสุด ตั้ง safe timeout และเลื่อน phase โดยไม่รอผู้พักหรือผู้หลุด

**ผ่านเมื่อ:** HTTP/WebSocket tests เล่นครบ run สำหรับ 2, 3 และ 4 คน; reconnect ได้ที่เดิม; ปฏิเสธ spoofed seat/stale encounter/duplicate trade; ทุกคนพักหรือ disconnect แล้วยังจบ encounter ได้; rematch รีเซ็ต run และดาวน์โหลด audit ได้

### M4 — หน้าการ์ดสมจริงที่กดเล่นได้

ใช้ [realistic card concept](../art/concepts/v0.4/realistic-card.png) เป็น reference ของบรรยากาศและการจัดหน้า ไม่ใช้ภาพหน้าจอทั้งแผ่นเป็น UI ข้อความ ราคา ปุ่ม และสถานะต้องมาจาก state จริง

- จุดสนใจกลางโต๊ะ: การ์ด NPC, สินค้าที่ประเมิน, ราคาที่เสนอ, ต้นทุนพลัง และผลเสียที่ยอมรับ
- ประตู: การ์ดตัวเลือกพร้อมเบาะแสที่ช่วยตัดสินใจ; inventory และ buff/debuff อ่านผลและระยะเวลาได้
- Dark Market: quote/จำนวนรับ/เวลาปิดชัดเจน เข้าถึงได้ตลอดช่วงที่ยังเปิด พร้อมสรุปผลก่อนขาย
- หน้าต่อรอง: แยกของ NPC กับของผู้เล่น แสดงเจ้าของและการยอมรับข้อเสนอ รวมสถานะผู้พัก/รอ/หลุด/ผิดพลาด
- สร้างภาพ NPC/สินค้าเป็น assets แยกชิ้นในขอบเขตที่ระบบใช้ เก็บ prompt/provenance ภาพไม่แอบบอก hidden truth
- เพิ่ม feedback ขนาดเล็กกับจังหวะเปิดประตู เปิดการ์ด เสนอราคา และรับผล ใช้สีหน้า/ภาพสถานะ NPC; เสียงเปิด/ปิดได้และเคารพ reduced motion ไม่ทำ lip-sync หรือระบบ character animation

**ผ่านเมื่อ:** ผู้เล่นทำทุก action ของ run ได้จาก UI ภาษาไทย ต้นทุนและเงื่อนไขปรากฏก่อนยืนยัน รองรับ mouse/touch และหน้าจอแคบ ไม่มีปุ่มหลอกหรือข้อมูลตัวอย่างแทน state จริง มี loading/error/reconnect/results ครบ

### M5 — พิสูจน์และส่งมอบให้ playtest

รัน unit/domain tests และ client build ที่เกี่ยวข้อง; scenario simulation สำหรับ 2/3/4 คนและพฤติกรรมหลายแบบ ตรวจ replay, economy ledger, item ownership, status timing และ phase completion แยกค่าทดลองของ v0.4 จากรายงาน baseline รุ่นเก่า

ใช้จำนวนเริ่มต้น 100 seeded runs ต่อชุด 2/3/4 คน × 4 bot policies = 1,200 runs และรายงานผลเลือกประตู/ราคาประเมิน/เงื่อนไข/เก็บหรือขาย/พัก ไม่สรุปความสนุกจาก bot ไม่ต้องเพิ่มรอบเมื่อหลักฐานผ่านแล้วโดยไม่มีปัญหาใหม่

คงการอ่าน/replay audits เก่าที่รองรับอยู่ เพิ่ม schema version สำหรับ v0.4 ไม่แก้ไฟล์ baseline เดิมด้วยผลรุ่นใหม่ รักษาห้อง/เซิร์ฟเวอร์ LAN ที่เปิดอยู่ หลีกเลี่ยง restart ที่ทำให้ audit หาย; เปิด v0.4 บนพอร์ตว่างและรายงาน URL จริงหลังเปิดสำเร็จ

อัปเดตคู่มือ playtest ของ appraisal, แบบบันทึก และ validation report ระบุจำนวนผู้เล่น/ผลทดสอบจริง ข้อจำกัด และวิธีเก็บ audit ก่อน rematch ตรวจ implementation ด้วยการ review แยกก่อนประกาศพร้อมทดสอบ

**ผ่านเมื่อ:** acceptance ทั้งหมดด้านล่างมีหลักฐานอ้างอิง ส่งมอบ LAN URL/วิธีรัน/audit/replay และคู่มือทดสอบความสนุก โดยไม่อ้างว่าเล่นกับคนจริงแล้ว

## ขอบเขตการตรวจและสิ่งที่ยังไม่ทำ

คำสั่งก่อนหน้าของผู้ใช้ให้หยุดตรวจภาพ/browser QA ยังมีผล แผนนี้ไม่เปิด browser QA เอง หลักฐาน UI จึงจำกัดที่ source/component behavior/build และต้องระบุว่า rendered layout, responsive และ accessibility ที่เห็นจริงยังไม่ได้ตรวจใหม่ ภาพ concept ไม่แทนหลักฐานหน้าจอ v0.4 ถ้าผู้ใช้เปลี่ยนข้อจำกัดนี้ภายหลัง ให้ตรวจแบบ bounded desktop/mobile ตาม skill

ไม่รวม Three.js/ฉากเดินได้, spritesheet pixel, accounts/ranking, progression ถาวร, combat, in-app voice, public hosting หรือ content เกินจำนวนที่ต้องส่ง ไม่ตั้ง automation และไม่ย้ายงานไป chat ใหม่

หลัง technical goal ผ่านจึงนัด human playtest: LAN 3–4 คนตามที่ผู้ใช้เลือก แล้วเปรียบเทียบกลุ่มมี/ไม่มี voice และกลุ่ม 2 คน เก็บเหตุผลการตัดสินใจ ความเสียดายจากตลาด เวลาที่พัก ความสับสน และ rematch ที่ผู้เล่นขอเอง หากยังกดราคา/เลือกเส้นทางเดิมทุกครั้ง ให้แก้กติกาที่หลักฐานชี้ ก่อนเพิ่มงานภาพหรือ event ใหม่
