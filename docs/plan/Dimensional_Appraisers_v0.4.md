# Cursed Market v0.4 — นักประเมินต่างมิติ

2026-10-13 — ร่างแนวคิดจากผู้ใช้และข้อเสนอกติกาสำหรับทดลอง ตอนนี้มี [decision ledger](Appraisal_Rules_Decisions_v0.4.md) และ [kernel/domain tests](../validation/appraisal-domain-v0.4.md) แล้ว [M3 rooms/network](../validation/appraisal-network-v0.4.md) ผ่านแล้ว แต่ UI/main/LAN ยังเป็น v0.3 ข้อเสนอในร่างนี้ใช้เป็นที่มาของ ledger ไม่ใช่ balance ที่ผ่าน playtest

## เป้าหมายและโลก

ผู้เล่นเป็นนักประเมินวัตถุจากต่างมิติ ประตูวาร์ปนำพ่อค้าและสิ่งมีชีวิตจากโลกอื่นมาเสนอสินค้า ผู้เล่นต้องประเมินราคา เลือกว่าจะเก็บอะไร ต่อรอง และจัดการผลของของที่ถืออยู่ ความเสี่ยงเกิดจากการตัดสินใจว่าจะเอาเปรียบพ่อค้าแค่ไหน และยอมรับเงื่อนไขใดเพื่อสร้างชุดของที่ต้องการ

ตัวอย่างผู้มาเยือนที่ผู้ใช้เสนอ: ออร์ก, vampire, autometa, alien, dark one รวมถึงสัตว์และตัวประหลาดอื่น ชื่อและจำนวนเผ่าสำหรับเกมเต็มยังไม่ถูกกำหนด การมีเผ่าต่างกันต้องเปลี่ยนข้อเสนอหรือวิธีต่อรองด้วย ไม่ใช่เปลี่ยนเพียงภาพ

แนวทางนี้เปลี่ยนบทบาทผู้เล่นและแกนการตัดสินใจจากการผลัดกันเป็นพ่อค้าประมูลของใน v0.3 การประมูลเดิมและเดิมพันคำสาปไม่จำเป็นต้องเป็น phase บังคับของแนวคิดใหม่

## สิ่งที่ผู้ใช้กำหนดแล้ว

- มีประตูวาร์ปให้เลือกว่าจะพบพ่อค้าจากมิติใด พ่อค้านำสินค้าจากโลกของตนมาให้ประเมิน
- ผู้เล่นเลือกเก็บสินค้าที่ต้องการได้ โดยจ่าย credit หรือรับเงื่อนไขของพ่อค้า เช่น debuff
- สินค้าที่เก็บอาจให้ทั้งผลดีและผลเสีย และบางแหล่งให้พลังเพิ่ม เช่น สินค้า buff หรือเงื่อนไขจากพ่อค้า
- มี phase ต่อรอง ขอชมสินค้าจากพ่อค้าที่นักประเมินคนอื่นประเมินไว้ และขอชมสินค้าที่นักประเมินคนอื่นถืออยู่ได้
- ประเมินราคาหรือต่อรองกับ NPC ต่ำเกินไปอาจมีผลเสีย ตั้งแต่เสีย credit เสียของ ไปจนถึงตาย ตัวอย่าง: base 20 ให้ราคา 10 มีโอกาส 20% ที่จะถูกจำได้ว่าประเมินต่ำเกินจริง ตัวเลขนี้เป็นตัวอย่าง ยังไม่ใช่สูตรทุกเผ่าหรือทุกส่วนลด
- การลงโทษจากการกดราคา/ต่อรองดังกล่าวไม่เกิดในการต่อรองระหว่างผู้เล่น
- การเล่นใช้พลัง พลังหมดทำให้หยุดเล่นช่วงหนึ่ง
- ผู้ใช้ตอบคำถามเรื่องระยะพักแล้ว: **ตายหรือพลังหมด พักเฉพาะ encounter แล้วกลับมาเล่นได้** ไม่ให้นั่งดูจนจบ run
- ผู้ใช้กำหนดขั้นต่ำ **50 RNG events และ buff/debuff รวม 20 ประเภท** ดู [คลังรายการครบตามจำนวน](RNG_Content_v0.4.md) ทุกIDมีeffectsและfixturesแล้ว; ตัวเลขผลยังเป็นค่าทดลองที่ต้องhumanplaytest
- มี [Dark Market](Dark_Market_v0.4.md) ที่สุ่มเปิดก่อน encounter แต่ละครั้ง สุ่มรายการรับซื้อจากสินค้าของ encounter ตั้งแต่ 1 รายการขึ้นไป รวมชนิดของที่เคยขายไปได้ ผู้ใช้ยืนยันให้รับซื้อจนจบ encounter นั้น เพื่อซื้อของจาก NPC แล้วขายให้ตลาดได้

คำว่า credit ถูกใช้สำหรับจ่ายซื้อและเป็นสิ่งที่เสียได้ จึงใช้เป็นเงินที่จ่ายได้ในร่างนี้ ยังไม่ได้ยืนยันว่าต้องเป็นชื่อเสียงด้วยหรือไม่

## คำศัพท์และคะแนนที่ยังต้องแยก

**Run** คือเกมหนึ่งครั้งที่สะสมของและผลระหว่าง encounter แล้วรีเซ็ตเมื่อเริ่มใหม่ **Encounter** คือช่วงพบพ่อค้า ประเมิน ต่อรอง และรับผลครั้งหนึ่ง **Action** คือการกระทำย่อยใน encounter เช่น ตรวจของหรือยื่นข้อเสนอ

คำตอบล่าสุดกำหนดระยะพัก แต่ไม่ได้ระบุว่าคะแนน 0 ล้างคะแนนสะสมทั้งหมดหรือเฉพาะ encounter ร่างนี้เสนอให้ผู้ตายได้ **0 จาก encounter นั้น** โดยไม่ล้างแต้มที่สะสมมาก่อน และให้ผู้พลังหมดหยุดกระทำจนจบ encounter โดยยังไม่สรุปว่าได้คะแนน 0 เช่นเดียวกัน ข้อนี้เป็นข้อเสนอ ไม่ใช่การตัดสินใจที่ผู้ใช้ยืนยันแล้ว

## Core loop ที่เสนอให้ทดลอง

1. **เริ่ม encounter / Dark Market:** คืนสิทธิ์ผู้พักแล้วสุ่มเปิดตลาด หากเปิดให้เห็นรายการรับซื้อและราคา ก่อนเลือกว่าจะขายของเก่าเอา credit ไปหมุนหรือเก็บไว้
2. **เลือกประตู:** เห็นเบาะแสเผ่า ประเภทสินค้า และลักษณะเงื่อนไขก่อนเลือก ตัวเลือกสุ่มจาก seed ของ run ความต้องการตลาดที่เปิดอยู่เป็นข้อมูลประกอบ
3. **พบและตรวจสินค้า:** เห็นข้อเสนอและข้อมูลที่เผ่านั้นยอมเปิด ตรวจเพิ่มได้โดยใช้พลัง จัดข้อมูลที่สังเกตได้แยกจากคำกล่าวอ้างของ NPC
4. **ประเมิน:** เลือกราคาประเมิน ตรวจว่าราคายิ่งต่ำเพิ่มโอกาสกำไรหรือเปิดทางให้ซื้อของ แต่แลกกับความเสี่ยงที่จะถูกจำได้ว่าเอาเปรียบ ราคารับซื้อ Dark Market ไม่แทน base หรือยกเลิกความเสี่ยง NPC
5. **ตัดสินใจรับของ:** ซื้อ รับเงื่อนไข ต่อรอง หรือปฏิเสธ ต้องเห็น credit ที่จ่าย พลังที่ใช้ และเงื่อนไขที่รับก่อนยืนยัน การประเมินไม่ได้บังคับให้ซื้อ ของที่ตรงรายการขายให้ Dark Market ได้ขณะที่ยังเปิด
6. **ต่อรองระหว่างนักประเมิน:** ขอชมรายการสินค้าพ่อค้าจาก encounter ของผู้อื่นและของในครอบครอง เสนอซื้อ/แลก และให้เจ้าของยอมรับหรือปฏิเสธ ของที่ได้จากเพื่อนอาจตรง demand ปัจจุบันได้
7. **รับผลและไป encounter ถัดไป:** ปิด Dark Market และ quote ของ encounter นี้ ใช้ผลสินค้า buff/debuff บันทึก credit/พลัง/ของและผลประเมิน ผู้ที่ตายหรือหมดพลังเป็นผู้ชมจนจบ encounter แล้วกลับมาตามกติกาฟื้นตัว

ข้อเสนอสำหรับ multiplayer: ให้แต่ละคนเลือกประตูและทำงานกับ NPC ของตนในช่วงเวลาเดียวกัน แล้วเปิดช่วงแลกเปลี่ยนร่วมกัน เพื่อไม่เพิ่มช่วงที่ทุกคนรอดูผู้ประเมินเพียงคนเดียว นี่เปลี่ยนจากการโหวตประตูกลุ่มใน v0.3 และยังเป็นข้อเสนอ

## ความเสี่ยงด้านราคา

ตัวอย่าง base 20 / ประเมิน 10 / โอกาสถูกจำได้ 20% ให้ใช้เป็นกรณีทดสอบที่ทำซ้ำได้ โอกาสถูกจำได้ **ไม่เท่ากับโอกาสตาย 20%** ต้องกำหนดผลตามเผ่าและสถานการณ์แยกต่างหาก

สิ่งที่ต้องพิสูจน์คือเหตุผลที่จะประเมินตรงหรือยอมจ่ายแพงขึ้น หากประเมินครึ่งราคาคุ้มเสมอ ลูปใหม่จะกลับไปเป็นการตัดสินใจแบบเดิม ข้อเสนอที่ต้องทดลอง:

- ส่วนต่างราคามีผลต่อความเสี่ยง และแต่ละเผ่าทนต่อการกดราคาไม่เท่ากัน
- การให้ราคาสมเหตุผลอาจได้เงื่อนไขที่ดีกว่า พลัง หรือข้อมูลสินค้า ไม่ใช่มีแต่เสียโอกาสซื้อถูก
- ใช้ของที่ถือและพลังที่เหลือเป็นเหตุผลเลือกรับความเสี่ยง ไม่ใช้เงินเพียงอย่างเดียว
- NPC ต้องมีเบาะแสเกี่ยวกับพฤติกรรมและขอบเขตผลเสียก่อนยืนยันข้อเสนอ โดยไม่จำเป็นต้องเปิดความจริงทุกอย่าง
- ยื่นข้อเสนอซ้ำต้องมีจำนวนครั้งหรือค่าพลังจำกัด ห้ามกด retry เพื่อสุ่มผลใหม่ ข้อเสนอที่ยืนยันหนึ่งครั้งให้ผลที่ server บันทึกเพียงครั้งเดียว

การเปิดเผย base value เป็นอีกคำถามหนึ่ง: หากเห็นค่าจริงแน่นอนตั้งแต่ต้น การประเมินจะเป็นการเลือกว่าจะกดราคากี่เปอร์เซ็นต์ ร่างเสนอให้เห็นข้อมูลหรือช่วงราคา แล้วใช้การตรวจลดความไม่แน่นอน โดย NPC อาจรู้ราคาจริงของตน ยังไม่ถือว่าผู้ใช้เลือกแนวทางนี้

## เผ่าและสินค้าสำหรับ slice แรกที่เสนอ

เริ่มจาก 3 พฤติกรรม NPC เพื่อทดสอบความต่างของการตัดสินใจ ก่อนเพิ่มเผ่าอื่น ตัวอย่างต่อไปนี้เป็นข้อเสนอของผู้ช่วย ไม่ใช่รายละเอียดที่ผู้ใช้กำหนด:

| NPC | ความต่างเชิงกติกาที่จะทดลอง |
| --- | --- |
| ออร์ก | ต่อรองได้แต่ไวต่อราคาที่มองว่าดูถูก ต้องพิจารณาเบาะแสอารมณ์และความเสี่ยงเสียของ |
| Vampire | ยอมลด credit หากรับเงื่อนไขใช้พลัง/ติด debuff ทำให้ผู้พลังน้อยกับพลังมากเลือกต่างกัน |
| Autometa | ให้ข้อมูลตรวจที่ชัดกว่า แต่ตรวจความคลาดเคลื่อนของราคาประเมินเข้มกว่าเผ่าอื่น |

เสนอสินค้า 6 แบบที่ทดสอบสามคู่ผล: เพิ่มพลังแต่เสีย credit, เพิ่มผลตอบแทนแต่กินพลังทุก encounter, และลดผลเสียชนิดหนึ่งแต่ทำให้สินค้าอีกกลุ่มมีข้อเสีย สินค้าต้องมีข้อแลกเปลี่ยนที่อ่านได้ก่อนรับ และบันทึกจังหวะเกิดผลให้แน่นอน

อย่าให้การขายของออกย้อนคืนพลังหรือยกเลิกต้นทุนย้อนหลังโดยอัตโนมัติ ต้องกำหนดว่า debuff ผูกกับตัวสินค้า การครอบครอง หรือสัญญาที่รับไว้ ผลสัญญาอาจยังอยู่หลังขายของได้หากเปิดเผยเงื่อนไขไว้ก่อน

## ต่อรองกับผู้เล่นและชมของผู้อื่น

รายการจาก NPC และของที่ผู้เล่นถือเป็นคนละเจ้าของ ต้องแสดงเจ้าของ ราคาอ้างอิงจากการประเมิน และเงื่อนไขที่เปิดเผยอย่างชัดเจน การขอดูไม่เท่ากับการรับข้อเสนอหรือการโอนของ และไม่ควรเปิดข้อมูลตรวจส่วนตัวทุกอย่างโดยอัตโนมัติ

สำหรับของผู้เล่น ร่างเสนอให้เจ้าของเลือกยอมรับหรือปฏิเสธข้อเสนอ ราคาต่ำไม่สุ่มทำร้ายหรือฆ่าอีกฝ่าย การซื้อ/แลกที่ตกลงกันสำเร็จต้องโอนของและ credit พร้อมกันครั้งเดียว ปฏิเสธเมื่อเจ้าของขายให้คนอื่นแล้วหรือผู้ซื้อมีเงินไม่พอ

ข้อยกเว้นเรื่องการลงโทษจากการกดราคาไม่ได้สรุปว่าสินค้าที่แลกกับผู้เล่นจะสูญเสียคำสาปหรือเงื่อนไขติดตัว ต้องแยกผลของสินค้าออกจากปฏิกิริยา NPC

สินค้าพ่อค้าที่ยังไม่ได้ซื้อ: ผู้ใช้ต้องการให้ขอดูได้ แต่ยังไม่ได้กำหนดว่าใครซื้อจากรายการนั้นได้ ราคาเก่าผูกพัน NPC หรือไม่ และผลต่อรองข้ามร้านคิดกับใคร ร่างแรกเก็บข้อนี้เป็นคำถาม ไม่แปลงการขอดูเป็นสิทธิ์ซื้อทันที

## พลัง การพัก และจบเกม

พลังเป็นทรัพยากรแยกจาก credit แต่ละ action ต้องแสดงต้นทุน ถ้าจ่ายพลังไม่พอให้ปฏิเสธคำสั่งแทนการติดลบ การตายและพลังหมดเป็นสองเหตุการณ์ที่บันทึกแยก แม้ใช้ช่วงพักเท่ากัน

ผู้พักส่งคำสั่งซื้อ ประเมิน ตรวจหรือต่อรองไม่ได้ แต่ดูสถานะสาธารณะของเพื่อนได้ ไม่เปิดข้อมูลลับของเพื่อนเพราะเป็นผู้ชม เพราะจะกลับมาแข่งขันใน encounter ถัดไป ผู้พักไม่ควรทำให้ phase รอคำตอบที่ตนส่งไม่ได้

ต้องมีการฟื้นตัวให้เล่นต่อได้จริง หากพลังยังเป็น 0 หลัง encounter จบ การบอกว่ากลับมาได้จะไม่มีผล ร่างเสนอค่าพลังฟื้นตัวขั้นต่ำเมื่อเริ่ม encounter ถัดไป โดยต้องทดลองว่าไม่ทำให้จงใจหมดพลังคุ้มกว่าบริหารทรัพยากร

เสนอ run แรกจำกัด **3 encounters** เพื่อให้จบและรีเซ็ตได้แม้มีของเพิ่มพลัง จำนวนนี้ยังไม่ยืนยัน ไม่ควรใช้พลังหมดเป็นเงื่อนไขจบเพียงข้อเดียวหากพลังเติมได้ไม่จำกัด

## ขอบเขตทดลองและสิ่งที่นำกลับมาใช้ได้

ลำดับที่เสนอ: นิยามราคา/พลัง/การพักและคะแนนให้ชัด แล้วทำ rules engine กับ simulation ก่อน playable slice 2–4 คน ใช้ 3 NPC, 6 สินค้า และ 3 encounters เป็น fixture เริ่มพัฒนาได้ แต่ไม่ถือเป็นการส่งมอบขั้นต่ำใหม่จนกว่า **50 events และ 20 ประเภท buff/debuff** จะทำงานจริงตาม [คลัง v0.4](RNG_Content_v0.4.md) ใช้ข้อความและภาพชั่วคราวก่อนทุ่มภาพเผ่าจำนวนมาก

จากระบบปัจจุบันใช้ซ้ำได้: ห้อง private, session/reconnect, server-owned secrets, seeded draws, คำสั่งที่ retry ไม่เกิดผลซ้ำ, private views และแนวทาง event replay ไม่ได้หมายความว่ากติกาการชำระเงินหรือคะแนนเดิมใช้ได้ตรง ๆ

- `applyAction` (`src/game/engine.ts:76`) ยังผูก action กับ auction number และ phase ผู้ขาย/ผู้ซื้อ ต้องเพิ่มตัวตน encounter และการตรวจผู้เล่นที่พัก
- `viewFor` (`src/game/views.ts:6`) ต้องแยกข้อเสนอ NPC, ผลตรวจ, ของที่ถือ และสิทธิ์ผู้ชม
- `OwnedRelic` (`src/game/types.ts:66`) เก็บค่าคะแนน ณ เวลาซื้อ ระบบผลดี/ผลเสียที่เกิดภายหลังต้องมี event ของผลสินค้า ไม่แอบแก้คะแนนจาก inventory อย่างเดียว
- `scoreFromHistory` (`src/game/audit.ts:26`) ต้องรองรับ credit, พลัง, สัญญา, การโอนระหว่างผู้เล่นและคะแนน encounter การตรวจเงินรวมเดิมไม่ครอบคลุม credit ที่สร้าง/ทำลายด้วยผล NPC
- `RoomService.handle` (`src/server/rooms.ts:52`) และ client ต้องใช้ phase/ผู้มีสิทธิ์ตอบแบบใหม่ โดยยังคงยืนยัน seat และ reconnect

เพิ่ม kernel v0.4 แยกใน `src/game/appraisal/` ใช้ seeded random/RuleError เดิม พร้อม audit schema4 โดยไม่แก้ kernel/audit รุ่นเก่า ยังไม่เปลี่ยน UI หรือ process LAN; ผล 66 regression tests เดิมแยกจากหลักฐาน domain ใหม่ของ v0.4

## เกณฑ์ทดสอบที่เสนอ

Rules/network: ข้อเสนอหนึ่งครั้งสุ่มและคิดต้นทุนครั้งเดียว; ห้ามซื้อ/ใช้พลังเกินที่มี; ผล buff/debuff ตรงจังหวะ; ขอชมไม่โอนของ; แลกของไม่เกิดซ้ำ; ต่อรองกับผู้เล่นไม่เรียกปฏิกิริยาลงโทษ NPC; ผู้พักดูได้แต่กระทำไม่ได้; encounter ถัดไปคืนสิทธิ์และทรัพยากรตามกติกา; ทุกคนพักพร้อมกันแล้วยังเดินเกมต่อได้; reconnect ไม่สุ่ม NPC/สินค้าใหม่; replay ตรวจผลและคะแนนได้

Human playtest: แต่ละเผ่าทำให้ปรับราคาหรือเงื่อนไขจริงหรือไม่, ของที่ถือทำให้เลือกประตูต่างกันหรือไม่, ใช้พลังเพื่อข้อมูลแล้วรู้สึกคุ้มไหม, ยังให้ราคาต่ำแบบเดิมทุกครั้งหรือไม่, เวลาพักหนึ่ง encounter น่าเบื่อแค่ไหน และมีใครขอเริ่ม run ใหม่เอง การมี RNG หรือบทลงโทษเพิ่มไม่ใช่หลักฐานความสนุก

## คำถามเดิมและคำตัดสินสำหรับทดลอง

หัวข้อต่อไปนี้ปิดเป็นค่าทดลองใน [decision ledger](Appraisal_Rules_Decisions_v0.4.md) แล้ว เพื่อเริ่ม implementation ไม่ถือว่าผู้ใช้ยืนยันทุกตัวเลขหรือสูตร และยังปรับได้จากหลักฐาน playtest

1. คะแนน 0 ใช้เฉพาะ encounter ที่ตายหรือล้างคะแนน run; ผู้หมดพลังคิดคะแนนอย่างไร และฟื้นพลังเท่าไร
2. Credit คือเงินอย่างเดียวหรือรวมชื่อเสียง; base value เปิดเผยแน่นอนหรือเป็นข้อมูลที่ต้องประเมิน
3. NPC ยอมรับราคาประเมินอย่างไร; โอกาสถูกจำได้และระดับผลเสียคิดจากอะไร และเกิดเวลาใด
4. สิทธิ์ซื้อสินค้าพ่อค้าที่ผู้อื่นประเมินไว้ และข้อมูลที่ขอชมจาก inventory ของผู้อื่น
5. จำนวน encounter ต่อ run และแต่ละคนเลือกประตูเองหรือเลือกประตูกลุ่ม
6. โอกาสเปิด Dark Market, distribution demand/ราคา, งบและ quota รับซื้อ รวมต้นทุนพลังขาย ส่วนการรับซื้อจนจบ encounter ผู้ใช้ยืนยันแล้ว

ยืนยันแล้วเฉพาะ **ช่วงพักหนึ่ง encounter แล้วกลับมาได้** สำหรับความตาย/พลังหมด ไม่ขอให้ผู้ใช้ยืนยันข้อนี้ซ้ำ
