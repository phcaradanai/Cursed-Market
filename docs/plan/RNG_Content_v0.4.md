# Cursed Market v0.4 — คลัง RNG events และ buff/debuff

2026-10-13 — ผู้ใช้กำหนดขั้นต่ำ **50 RNG events และ buff/debuff รวม 20 ประเภท** รายการนี้มี typed catalog และ resolver ใน kernel แล้ว ผ่าน [domain validation](../validation/appraisal-domain-v0.4.md) ครบทุก ID แต่[M3 rooms/network](../validation/appraisal-network-v0.4.md) ผ่านแล้ว แต่ยังไม่เชื่อม UI/main/LAN รายละเอียดผล ตัวเลข และการแบ่ง buff10/debuff10 เป็นค่าทดลอง ไม่ใช่ balance ที่ผ่าน playtest

อ่านร่วมกับ [นักประเมินต่างมิติ](Dimensional_Appraisers_v0.4.md) รุ่นที่เล่นได้ยังเป็น v0.3 ผลทดสอบเดิมไม่ยืนยันระบบในเอกสารนี้

[Decision ledger](Appraisal_Rules_Decisions_v0.4.md) ระบุคะแนน พลัง การฟื้น ราคา NPC/การซื้อข้ามร้าน และสูตรตลาดที่ kernel ใช้อยู่ การยืนยันจำนวน/ผลใน domain ไม่แทนหลักฐานว่าเล่นผ่าน network และ UI ได้แล้ว

เพิ่มเติม: [Dark Market](Dark_Market_v0.4.md) สุ่มเปิดก่อนทุก encounter และถ้าเปิดจะรับซื้อจนจบ encounter นั้น สุ่ม demand ตั้งแต่ 1 รายการขึ้นไปจากชนิดสินค้าของ encounter รวมชนิดที่เคยขายไปแล้วได้ นี่เป็นระบบ RNG เพิ่มใน loop ไม่ลดจำนวน E01–E50 หรือ B01–D10 และไม่ใช้กติกาไม่ซ้ำ event ID มาบังคับให้ตลาดเปิดได้เพียงครั้งเดียวต่อ run

## วิธีใช้คลังสุ่ม

- 50 events คือคลังสำหรับหลาย run ไม่ใช่ให้เกิดครบ 50 ครั้งใน run เดียว
- แต่ละ event มี ID, เงื่อนไขเกิด และผลต่อการตัดสินใจ การเปลี่ยนชื่อเผ่าหรือภาพอย่างเดียวไม่นับเป็น event เพิ่ม
- เสนอให้มีไม่เกิน 3 events ต่อผู้เล่นต่อ encounter: ข้อเสนอ/สถานการณ์ไม่เกิน 2 และผลต่อเนื่องจากความเสี่ยงที่รับไว้ไม่เกิน 1 ไม่เพิ่มการกดตอบ 50 หน้าต่อเกม
- สุ่มจากรายการที่เข้าเงื่อนไขของ phase, NPC, inventory และสถานะเท่านั้น ไม่สุ่ม event ที่ต้องมีของให้กับคนไม่มีของ หรือเสนอผลใน encounter ถัดไปเมื่อไม่มี encounter ถัดไป
- ไม่ซ้ำ ID เดิมสำหรับผู้เล่นคนเดิมใน run จนกว่าจะใช้รายการที่เข้าเงื่อนไขหมด หากไม่มีรายการที่เข้าเงื่อนไข ให้ข้าม event slot ได้ ไม่สุ่มซ้ำจนกว่าจะเจอผลที่ต้องการ
- น้ำหนักเริ่มต้นเสนอให้เท่ากันภายใน phase และเงื่อนไขเดียวกัน แล้วปรับจากข้อมูลจริง การมี 50 events ไม่ได้แปลว่าแต่ละ event มีโอกาสเกิด 2% เพราะรายการที่เข้าเงื่อนไขต่างกัน
- Server ใช้ seed ลับกับ run/encounter/seat/phase/slot ที่คงที่ เก็บ event ID, ตัวเลือกที่เสนอและผลที่เกิดไว้ Retry, reconnect หรือขอดูข้อมูลซ้ำไม่สุ่มใหม่ การแลกประตูที่อนุญาตต้องมีต้นทุนและทางเลือกสำรองที่กำหนดไว้แล้ว
- เห็นต้นทุน เงื่อนไข ระยะผลและขอบเขตผลเสียก่อนยืนยันสัญญาหรือข้อเสนอเสี่ยง ตรวจ credit/พลัง/สิทธิ์/เจ้าของของอีกครั้งตอนยืนยัน ถ้าจ่ายไม่ได้ให้ปฏิเสธคำสั่ง ไม่มีเงินหรือพลังติดลบ
- ข้อเสนอใหม่ปฏิเสธได้โดยไม่รับผลของสัญญา แต่เมื่อรับความเสี่ยงแล้ว การปฏิเสธจ่ายค่าปรับไม่ได้ยกเลิกผลที่รับไว้ ผลต่อเนื่องต้องอยู่ในขอบเขตที่แสดงไว้ล่วงหน้า
- การต่อรองกับผู้เล่นไม่เรียกการตรวจจับหรือบทลงโทษ NPC ผลสินค้าและสัญญาเดิมยังใช้ตามที่เปิดเผยไว้ ของล็อกโอนไม่ได้จนกว่าจะปลดล็อก
- ไม่มี buff/debuff ที่ทำให้ตายหรือหมดพลังแล้วต้องรอจนจบ run ผู้พักยังดูข้อมูลสาธารณะได้ และกลับมาใน encounter ถัดไปตามที่ผู้ใช้ยืนยัน

## กติกาสถานะร่วมที่เสนอ

สถานะผูกกับผู้เล่น เว้นแต่ระบุว่าล็อกสินค้าชิ้นหนึ่ง ขายสินค้าที่เป็นแหล่งสถานะไม่ย้อนคืนต้นทุนหรือยกเลิกสถานะที่ได้รับแล้ว สินค้าที่เปิดใช้ได้ต้องบอกว่าการปิดใช้หยุดการให้สถานะครั้งถัดไป ไม่ล้างสัญญาย้อนหลัง

ประเภทเดียวกันไม่บวกทับ: ได้ซ้ำใช้จำนวนครั้ง/เวลาคงเหลือที่มากกว่า ไม่บวกทั้งสองชุด สถานะต่างประเภทอยู่ร่วมกันได้ เมื่อลดความเสี่ยงให้รวมตัวปรับหน่วย **percentage points** แล้วจำกัดโอกาสไว้ 0–100% ไม่ใช้เปอร์เซ็นต์คูณกันโดยไม่แจ้งผู้เล่น ตัวอย่างความเสี่ยงเดิม 20% และลด 10 จุด เหลือ 10%

ผลประเภทป้องกันถูกใช้ครั้งเดียวเมื่อเกิดเหตุจริง ถ้าไม่มีเหตุจนหมดอายุก็หายไป ต้นทุนที่ลดแล้วต่ำสุด 0; ต้นทุน 0 ไม่ยกเลิกจำนวนครั้งต่อรอง/ตรวจที่กติกาหลักอนุญาต พลังที่ได้เพิ่มต้องจำกัดตามเพดานพลัง

สถานะข้อมูลใช้จำนวนครั้งเมื่อให้ข้อมูลที่ระบุสำเร็จเท่านั้น B01 ไม่ถูกใช้ทิ้งเมื่อ D02 บล็อกค่าจริง แต่ยังหมดอายุได้ตามปกติ การซื้อชุดหลายชิ้นที่ยืนยันพร้อมกันนับเป็นคำสั่งซื้อหนึ่งครั้งสำหรับ B03/D06 และคิดส่วนลด/ต้นทุนพลังกับทั้งคำสั่ง ไม่ให้ได้ส่วนลดซ้ำต่อชิ้นโดยไม่ได้ระบุ

"จนจบ encounter นี้" หมายถึงหมดหลัง settlement ของ encounter ที่ได้รับสถานะ "ถึงจบ encounter ถัดไป" รวมช่วงปัจจุบันและช่วงถัดไป ผลที่เกิดต้น encounter ลดจำนวนครั้งหลังทำงาน ไม่ทำงานเมื่อสถานะหมดแล้ว

ข้อเสนอเรื่องลำดับ: ใช้ค่าใช้จ่าย/ความเสี่ยงก่อนยืนยัน action, resolve NPC, ใช้โล่กับผลที่จะเกิด, apply ต้นทุน/ผลครั้งเดียว, ตรวจพลังหมด/ตาย, แล้วบันทึกสถานะและสิทธิ์ผู้เล่น เมื่อเข้า encounter ถัดไปคืนสิทธิ์ผู้พักและให้พลังฟื้นตัวขั้นต่ำตามกติกาหลักก่อนผลฟื้นพลังจากสินค้า D10 ไม่ลดค่าฟื้นตัวขั้นต่ำนี้ จำนวนพลังฟื้นตัวและคะแนนหลังตายยังเป็นคำถามในร่างหลัก

| E47 | สมุดสินค้าข้ามร้าน | มีรายการ NPC ที่นักประเมินคนอื่นประเมินไว้และยอมเปิดให้ชม | เลือกขอดูรายการหนึ่งชิ้นและราคาอ้างอิง หรือเก็บเวลาไว้ ไม่เปิดความจริง/ผลตรวจส่วนตัวอัตโนมัติ ไม่โอนของและไม่ยืนยันสิทธิ์ซื้อข้ามร้านที่ยังไม่กำหนด |
| E48 | ค่าปรับจากการกดราคา | Server บันทึกว่าถูก NPC จับได้แล้ว และขอบเขตผลเสียประกาศไว้ | เลือกเสีย credit 2 หรือเสียสินค้าที่เลือกหนึ่งชิ้นเมื่อมีทางเลือกนั้น ถ้าไม่มีทรัพยากรทั้งสอง ใช้ทางเลือกเสียพลังไม่เกิน 2 ที่ประกาศไว้ B07 ใช้ได้เฉพาะทางเลือกยึดของ |
| E49 | พ่อค้าจดจำใบหน้า | ถูก NPC จับได้แล้ว; ยังมี encounter ถัดไป; ประกาศผลนี้ไว้ | จ่าย credit 2 ยุติสัญญา หรือรับ D08 ถึงจบ encounter ถัดไป ไม่ติดสถานะจากการต่อรองกับผู้เล่น |
| E50 | คำพิพากษา Dark One | รับสัญญา NPC ที่เปิดเผยว่าตายได้และถูกจับผิดตามสัญญาแล้ว | ยอมเสียของที่เลือกหนึ่งชิ้นเพื่อถอนสัญญาเมื่อมี หรือรับผลตายและพักเฉพาะ encounter นี้ B08 แทนผลตายได้ ไม่มีการสุ่มฆ่าผู้เล่นที่ไม่ได้รับสัญญานี้ |

E48–E50 เป็นทางเลือกผลต่อเนื่องจากการตรวจจับที่เกิดแล้ว ใช้ได้เพียงหนึ่งรายการต่อข้อเสนอที่ยืนยัน ไม่ทำการตรวจจับซ้ำสามครั้ง ตัวอย่าง base 20 / ประเมิน 10 / ถูกจำได้ 20% ยังเป็นกรณีทดลองของกติกาหลัก ไม่ได้หมายความว่า E50 มีโอกาสฆ่า 20% ในทุกข้อเสนอ

## จุดที่ต้องปิดก่อนลง engine

คลังนี้ไม่ยืนยันคะแนน 0 ว่าคิดระดับ encounter หรือ run, จำนวนพลังเริ่ม/เพดาน/ฟื้นตัว, สูตร NPC ยอมรับราคา, โอกาสตรวจจับพื้นฐานแต่ละเผ่า หรือสิทธิ์ซื้อรายการข้ามร้าน การระบุ buff/debuff ที่ปรับค่าเป็นหน่วยแน่นอนช่วยให้ทดลองได้ แต่ไม่ได้ตอบคำถามฐานเหล่านี้แทนผู้ใช้

ของที่ได้จาก NPC หรือ event ต้องมีบัญชีต้นทุน/รางวัล/ผลถาวรที่ replay ได้ กำหนดงบ NPC สำหรับ credit rewards และรับซื้อเพื่อไม่สร้างเงินได้ไม่จำกัด ห้ามให้ event ซื้อคืนหรือฟื้นพลังเดิมถูกเรียกซ้ำจาก retry หรือการส่งสินค้าสลับกัน

## Acceptance สำหรับจำนวนและพฤติกรรม

- มี event IDs E01–E50 ครบ 50 ชนิด ไม่ซ้ำ และ status IDs B01–B10 / D01–D10 ครบ 20 ชนิด ทุกประเภทมี event ที่ใช้ได้
- แต่ละ event ผ่านอย่างน้อยกรณีเข้าเงื่อนไข/ไม่เข้าเงื่อนไข/ยอมรับ/ปฏิเสธตามที่มีทางเลือก ไม่มีการทำ event ต้องมี inventory ใน state ที่ไม่มี inventory
- ทดสอบ duration, จำนวนใช้, ได้ซ้ำ, การหักล้าง, การหมดอายุและเพดานต้นทุน/พลัง ไม่ให้ข้อความสถานะขัดกับผลจริง
- ทดสอบว่าคนตาย/หมดพลังพักเฉพาะ encounter แล้วกลับมาได้ การใช้ D10 ไม่ทำให้สิทธิ์กลับเข้าเล่นเสียไป
- ทดสอบ seeded replay, reconnect, retry, ข้อเสนอเก่าหมดอายุ, เงินไม่พอและของถูกขายแล้ว ไม่มีการโอน/สุ่ม/ลงโทษซ้ำ
- ทดสอบการต่อรองระหว่างผู้เล่นโดยเฉพาะว่าไม่เรียก E48–E50 หรือการจับผิดของ NPC
- การมีรายการครบเป็น design acceptance เท่านั้น การส่งมอบ gameplay ต้องมีผลของทั้ง 50 events และ 20 statuses ใน engine และ network flow จริง ไม่ใช้จำนวนแถวในเอกสารหรือผล tests v0.3 เป็นหลักฐานว่าเกม v0.4 ทำแล้ว
