# Cursed Market v0.4 — Human playtest

2026-10-14 — คู่มือนี้สำหรับต้นแบบนักประเมินต่างมิติ ไม่ใช้ผล bot/network/SSR เป็นผลจากคนจริง เป้าหมายแรกคือหาว่า **ผู้เล่นยังตัดสินใจแบบเดิมทุกครั้งหรือไม่** และความเสี่ยง/RNG/ตลาดทำให้เกิดการเปลี่ยนแผนที่อยากเล่าให้เพื่อนฟังไหม

## เตรียม

กลุ่มแรก LAN 3–4 คนตามที่ผู้ใช้เลือก ใช้คนละอุปกรณ์บนเครือข่ายเดียวกัน เปิด `http://192.168.10.150:3105` สร้างห้องและส่งรหัส ก่อนเริ่มเลือก mode มี voice หรือไม่มี voice ให้ตรงกับวิธีเล่นจริง เจ้าของเลือกจับเวลา/ไม่จับเวลาและบันทึกเวลา4ช่วงก่อนทุกคนกดพร้อมแล้วเริ่ม จดค่าที่ใช้ทุก run ในแบบบันทึก เพื่อแยกเวลารอเพื่อนกับผลของ deadline ใช้ [วิธีรัน LAN](../plan/Appraisal_LAN_v0.4.md) หาก IP เปลี่ยน

คัดลอก [แบบบันทึก v0.4](appraisal-session-v0.4.md) ต่อ session จด build/source manifest, ผู้เล่นจริง, อุปกรณ์, mode และ match ID เว้นข้อมูลที่ไม่ทราบเป็น “ไม่ทราบ” เตรียมเก็บ audit หลังจบ **ก่อน rematch** ห้องอยู่ใน memory และไม่เก็บผลถาวร ห้าม restart เซิร์ฟเวอร์ระหว่าง session

## คำอธิบายไม่เกินสองนาที

“เราเป็นนักประเมิน ทุกช่วงเลือกหนึ่งประตูไปพบพ่อค้าจากมิติอื่น เห็นเบาะแสและช่วงราคาแต่ยังไม่รู้ความจริงทั้งหมด ใช้พลังตรวจ ให้ราคา หรือเลือกซื้อด้วยเครดิต/รับเงื่อนไข การประเมินอย่างเดียวไม่ได้ซื้อของ ดูราคาที่พ่อค้ายอมรับและผลสัญญาก่อนยืนยัน คุณจะเก็บของไว้ใช้หรือขายให้ Dark Market ที่สุ่มเปิดก็ได้ ตลาดซื้อจนจบช่วงนี้ ราคาถัดไปไม่มีใครรู้ ของที่เพิ่งขายอาจกลับมาเป็นของที่ตลาดต้องการ ผู้เล่นซื้อ/แลกกันได้เมื่อเจ้าของยอมรับ และราคาต่ำกับเพื่อนไม่มีบทลงโทษพ่อค้า”

“กดราคา NPC ต่ำอาจถูกจับได้และมีผลเสีย ตัวอย่างของ base 20 ให้ราคา 10 มีโอกาสถูกจับได้ 20% ซึ่งไม่ใช่โอกาสตาย 20% NPC/สถานะอาจเปลี่ยนความเสี่ยงที่หน้าเกมแสดง ราคาจริงยังซ่อนอยู่จนตรวจ/เปิดผล ของแท้ก็อาจมีคำสาปและการรับของอาจได้ทั้ง buff และ debuff เครดิตกับพลังเป็นคนละอย่าง ถ้าตายหรือพลังหมดพักเฉพาะ encounter นี้ แล้วกลับมาในช่วงถัดไป ตายให้คะแนนช่วงนี้ศูนย์แต่ไม่ล้างช่วงก่อน หมดพลังเก็บคะแนนที่หาได้ไว้ แต่ขายหรือซื้อเพิ่มไม่ได้จนฟื้น”

“หนึ่ง run มีสาม encounters คะแนนมาจากความมั่งคั่งที่เพิ่มในแต่ละช่วงและโบนัสประเมินแม่น ดู breakdown ตอนจบ ค่าทุกอย่างยังเป็นการทดลอง ไม่ต้องทำให้คะแนนดีที่สุดเพื่อช่วยผู้จัด”

จดคำตอบก่อนช่วยเพิ่ม:

1. ประเมินราคาสำเร็จแล้วคุณซื้อของไปทันทีหรือยัง? (ยัง ต้องยืนยันซื้อและต้นทุน)
2. Dark Market เปิดแล้วขายของที่เพิ่งซื้อได้ถึงเมื่อไร? (ถึงจบ encounter นั้น ขณะยัง active)
3. ถ้าพลังหมด/ตายต้องรอจนจบ run ไหม และกดราคาเพื่อนทำให้ NPC ลงโทษไหม? (พักช่วงเดียว; ไม่มี NPC ลงโทษจาก P2P)

จับเวลาความเข้าใจและครั้งแรกที่เล่นเองได้ แยกความไม่เข้าใจ UI ออกจากการเลือกที่ไม่คุ้ม ผู้จัดช่วยได้เมื่อค้าง แต่จดทุกครั้ง

## ระหว่าง run แรก

ผู้จัดสังเกตและจด encounter/phase/seat โดยไม่ชี้กลยุทธ์หรือชวนเล่นต่อก่อนจบ:

- ประตูไหนถูกเลือกเพราะอะไร เปลี่ยนตามตลาด/ของ/สถานะจริงหรือเลือกเหมือนเดิม?
- ประเมินต่ำเพื่อหวังซื้อเองไหม เห็นความเสี่ยงก่อนส่งและยอมรับผลได้หรือไม่?
- มีจังหวะลังเลระหว่างเก็บ/ใช้/ขายเพื่อเครดิตหมุนไหม? หาก demand ตรงของที่ขายไปก่อน รู้สึกเสียดายและปรับแผนจริงหรือไม่?
- สุ่มให้เหตุการณ์ที่นำไปตัดสินใจ หรือแค่ทำให้ผลพลิกโดยควบคุมไม่ได้? จดสิ่งที่ผู้เล่นทำตอบสนอง
- มีการต่อรอง/แลกกับเพื่อน และคุ้มกับเวลารอไหม? no-voice ยังตัดสินใจได้เองไหม?
- ผู้พักดูเพื่อนได้และเข้าใจว่าจะกลับมาเมื่อไรไหม? จดเวลาพักที่สังเกตจริง
- อันไหนคือเลือกจบช่วงเอง กับอันไหนหมดเวลา/หลุด/ส่งคำสั่งผิด? Audit ช่วยตรวจ timing แต่ไม่บอกเหตุผลแทนคน

สินค้า 30 ชนิดและ 50 events/20 statuses เป็นคลังทั้งเกม ไม่คาดหวังให้เห็นครบใน run เดียว ไม่เพิ่ม run เพื่อไล่ ID ระหว่างทดสอบความสนุก

## หลังจบและ rematch

ดาวน์โหลด audit ของ match แรกก่อนกด rematch เก็บการขอเล่นต่อ **ก่อนผู้จัดเสนอ** แล้วถามแต่ละคนแยกกัน: สนุก 1–5, ช่วงที่ตัดสินใจซ้ำ/เบื่อ/งง, จังหวะเสี่ยงหรือเสียดายที่จำได้, ทางเลือกใดเปลี่ยนเพราะ RNG/ตลาด และจะเล่นเองอีกไหม

เมื่อกลุ่มเลือกเล่นต่อ ให้บันทึกว่า rematch เริ่มและจบจริงหรือไม่ เก็บ audit แยก match ID การเล่นต่อที่นัดไว้หรือผู้จัดชวนถือเป็น scheduled repeat ไม่ใช่ voluntary rematch ผู้ไม่มีเวลา/ไม่มีโอกาสเลือกให้แยก denominator ไม่กรอกเป็นปฏิเสธ

สรุป logs ด้วย:

```sh
npm run --silent playtest:report -- path/to/match-1.json path/to/match-2.json > /tmp/appraisal-session-report.json
npm run replay -- path/to/match-1.json
```

JSON report มี `humanFunValidated:false` และ `voluntaryRematchRate:null` โดยตั้งใจ: ต้องอ่านแบบบันทึกของคนร่วมด้วย ชื่อผู้เล่นอยู่ใน audit ให้ใช้รหัสเมื่อแบ่งปันภายนอก

## รอบเปรียบเทียบและจุดตัดสินใจ

หลังกลุ่มแรก ทดลองกลุ่ม no-voice/voice และกลุ่ม 2 คนแยกกัน สลับลำดับเงื่อนไขและจดจำนวนครั้งที่เคยเล่น ลดผลจากการเรียนรู้ไม่ให้ปะปนกับผล voice เก็บเวลาช่วงการตัดสินใจและเหตุผลจริง ไม่ใช่ดูเพียงคะแนน

หากยังเลือกประตู/ราคา/ขายแบบเดียวทุกครั้ง หรือหลายคนตอบว่าเพียงรอ RNG ให้เลือกปัญหาที่มีเหตุการณ์รองรับหนึ่งข้อแล้วแก้กติกานั้นก่อนเพิ่ม art/event หากเกิดความหลากหลายและมีคนขอเล่นต่อเอง ให้ยืนยันกับกลุ่มใหม่ก่อนลงทุน polish ภาพ คะแนนสูงหรือ bot ชนะไม่พิสูจน์ว่าทางนั้นสนุกหรือเป็น dominant strategy
