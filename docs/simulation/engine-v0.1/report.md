## ประเด็นที่ควรนำไปดูใน human playtest

- กลุ่ม 2 คนแบบ mixed มี bid ที่ pass 24.4% และเงินคนรวยสุดเฉลี่ย 82.7% เทียบกับ 50.9% ใน 4 คนแบบ mixed. ตรวจว่าการขาดคู่แข่งประมูลทำให้เกม 2 คนเสียความตื่นเต้นหรือเงินกระจุกเร็วหรือไม่.
- กลุ่ม 4 คนที่ใช้ heuristic แบบเดียวกันมีราคาสูงสุดเสมอ 45.0%–50.7% ของการขาย. อาจเป็นผลจาก bot คิดเหมือนกัน; ต้องดูคนจริงก่อนแก้กติกา.
- ยังไม่มีการเปลี่ยนค่ากติกาหรือประกาศว่า balance สำเร็จจากผลนี้.

## ข้อสมมติของ simulation

- GDD ไม่กำหนดอัตราแท้/คำสาป จึงเริ่มจาก 50.0% genuine และ 50.0% cursed โดยสุ่มแยกอิสระ. ตัวแปรนี้ยังไม่ผ่านการ balance.
- cautious, trusting และ skeptical คำนวณมูลค่าคาดหวังจากข้อมูลของ seat ตนเอง ด้วยความเชื่อใน certificate 75%, 95%, 55% ตามลำดับ; ไม่เรียนรู้พฤติกรรมคนขาย.
- Seller heuristic เลือกสินค้าที่มีคำรับประกันจริงน่าดึงดูด แม้อีกคุณสมบัติอาจอันตราย; random เลือกสินค้า/คำรับประกัน/ตรวจ/ราคาแบบสุ่ม.
- mixed หมุนเวียน bot ทั้งสี่ชนิดใน seat ต่าง ๆ. แต่ละจำนวนผู้เล่นใช้ card seeds เดียวกันข้าม scenario. Bots รับเฉพาะ projected view ของตนเอง.
- ค่า 0 สำหรับอัตราที่ไม่มี denominator หมายถึงไม่มีเหตุการณ์ชนิดนั้น; ดูจำนวนจริงใน JSON. Win shares แบ่งเท่ากันเมื่อชนะร่วม.

## ใช้ผลนี้ตัดสินอะไรได้

ผลช่วยคัดกรองการผ่านประมูลบ่อย ราคา การเสมอ การใช้ inspection และเงินที่กระจุกตัว ภายใต้ heuristic ที่ประกาศ. ไม่ใช่หลักฐานว่าผู้เล่นจะสนุก หรือกลยุทธ์ใดชนะเสมอ. อัตรา cursed สูงไม่ได้พิสูจน์ว่าคนมองข้ามคำสาป.

ก่อนเปลี่ยนกติกา ให้ทดสอบคนจริง 2 และ 3–4 คน ทั้งมี/ไม่มี voice: ความเข้าใจ guarantee, เหตุผลที่ตรวจ/ยื่นราคา, จุด reveal ที่จำได้, ช่วงรอ และการขอ rematch โดยสมัครใจ.

## ไฟล์และวิธีตรวจซ้ำ

- summary.json: parameters, metrics และ win/score แยก policy/seat.
- summary.csv: ตารางรวมสำหรับวิเคราะห์ต่อ.
- example-match.json: end-of-game audit log จาก 4-player mixed แมตช์แรก มี seed และข้อมูลลับครบ จึงใช้หลังจบเกมเท่านั้น.
- รัน: `npm run simulate -- --games 1000 --seed 'cursed-market-v0.1'` พร้อม probability flags เมื่อใช้ค่าต่างจาก default.
- Replay: `npm run replay -- docs/simulation/engine-v0.1/example-match.json`.
