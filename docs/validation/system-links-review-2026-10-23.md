# รีวิวจุดเชื่อมของ encounter, event, ผลสถานะ และผลของสินค้า (ใช้และถือ)

วันที่: 2026-10-23 · ฐานโค้ด: branch `fix/event-choices` @ `08a83e1`

**ขอบเขต:** ตรวจว่าระบบเหล่านี้เชื่อมกันและส่งผลต่อกันจริง
- **ระบบที่ตรวจ:** encounter (ประตู/พ่อค้า), เหตุการณ์ทุกชุด, ผลสถานะ (B/D), สินค้า (เปิดใช้, ถือ, ใช้ใน event)
- **ทรัพยากรที่ตรวจ:** เครดิต, พลัง, ชีวิต, ความไว้ใจ, ข้อมูล, เศษชีพจร, ตั๋วคำสั่งมืด, คลัง และคะแนน
- **ข้อเสนอ:** วิธีเพิ่ม seed และ route ให้หลากหลายขึ้นจากของที่มีอยู่แล้ว

ไม่รวม: สมดุลตัวเลขละเอียด, UI, art และกติกา secure economy ที่ผู้ใช้ยืนยันแล้ว

## วิธีตรวจและหลักฐาน

1. **ตารางสถานะ:** หาแหล่งเกิด (producer) และจุดอ่าน (consumer) ของสถานะทั้ง 51 ตัว (B01–B26, D01–D25)
   - แหล่งเกิด: ทั้งโค้ดที่เรียก `grant` ตรง ๆ และตารางข้อมูล ได้แก่ `ITEM_SPECS` buff/drawback, เงื่อนไข NPC, `POLISH_EVENTS`, `CORE2_SPECS`, `BOND_SPECS`, ผลของค้าง, consign, สัญญาตลาด, ทักษะพ่อค้า, dread และ pool สุ่มพร
   - จุดอ่าน: ทุกที่ที่เรียก `status`, `statusMagnitude`, `consumeStatus` หรือ `removeStatus`
2. **ตารางสินค้า 66 ชนิด:** หมวด, buff/drawback ตอนเปิดใช้, ผลตอนถือ, ผลเสริมตอนเปิดใช้, พ่อค้าที่วางขาย และ event ที่อ้างถึง
3. **จำลอง 48 runs** (3 ที่นั่ง, 4 policy × 6 seed × classic/survival) ด้วย config เดียวกับ server นับจำนวนการให้สถานะ การเปิดใช้ การซื้อ และชนิด trace ทั้งหมด
   - สถิติจาก bot บอกได้ว่า "เส้นทางไหนถูกใช้" แต่บอกไม่ได้ว่า "คนจะใช้ไหม"

ป้ายระดับ: **สูง** = เนื้อหาหรือผลที่สัญญาไว้ไม่ทำงานเลย · **กลาง** = เชื่อมไม่ครบหรือเส้นทางแคบ · **ต่ำ** = ความเสี่ยงหรือความซ้ำซ้อนเล็กน้อย
ป้ายหลักฐาน: **[sim]** = ยืนยันด้วยการจำลอง · **[อ่านโค้ด]** = ยืนยันจากโค้ด

## 1. แผนผังการเชื่อมของระบบ

```
ประตู/พ่อค้า (encounter)
  ├─ สินค้าในร้าน ── ตรวจ / ประเมิน / ซื้อ / ขโมย / แลก ── ความไว้ใจ, ค่านายหน้า, ข้อมูล
  ├─ เงื่อนไขพ่อค้า (D01 D02 D03 D04 D06 D10 D11 D12) ── ส่วนลดแลกผลเสีย
  ├─ ดีลฟื้นพลัง/ชีวิต ── เครดิต → พลัง/ชีวิต (ตามความไว้ใจ)
  └─ เหตุการณ์ (สุ่มตาม phase, NPC, ของที่ถือ, ลาง)
        └─ ให้/เอาออก สถานะ B/D, ทรัพยากร, ของ, ข้อมูล
สินค้า
  ├─ ถือ: ผลตอนถือ (21 passive + 45 ผลเสริม) ── ส่วนลด, โควตาตรวจ, นายหน้า, โชคหัวก้อย, เพดานพลัง/ชีวิต ...
  ├─ เปิดใช้: buff ของชนิด, ฟื้นพลัง (orb), ปลด D07 (key), ฟื้นชีวิต (food/potion), ผลเสริม 8 ชนิด, ผลพิเศษ 3+3 ชนิด
  │         คำสาป → drawback ของชนิด (+ เสียชีวิต 1 ในโหมด survival)
  └─ ใช้ใน event: ตามหมวด (E07, E31–E40) และ bond กับ NPC (E51–E107)
ลางประจำช่วง (15 แบบใน core2) ── ราคาขาย, ค่าธรรมเนียม, ความกดดัน, ภาษี, ขโมย, ตลาดเปิด, ความไว้ใจ
ท้ายช่วง ── D05/D11/ลางกินพลัง, ผลสถานะ v0.6, dread, ชีวิตลด, เศษชีพจร → ชีวิต
จบเกม ── wealth (classic) / Collector (survival: เครดิต + ของ + B10/D10)
```

### สิ่งที่เชื่อมดีแล้ว [อ่านโค้ด + sim]

- **ร้านค้า:** ทุกชนิดสินค้า (66) ถูกวางขายและถูกซื้อใน simulation
- **event ตามหมวด:** ทุกหมวดมี event ที่ใช้ของหมวดนั้นอย่างน้อย 3 ตัว
- **ผลตอนถือ:** มีครบทุกชนิด ยกเว้นของความสามารถ 3 ชิ้นที่ใช้เปิดใช้อย่างเดียว
- **สถานะชุดเดิม:** B01–B20 และ D01–D20 มีทั้งแหล่งเกิดและจุดอ่าน
- **ลาง 15 แบบ:** ทุกแบบมีโค้ดอ่าน (ยกเว้น `thieves-night`, ดู L2)
- **ทรัพยากรมีทางแลกกันหลายทาง:**
  - เครดิต ↔ พลัง/ชีวิต
  - ความไว้ใจ → ส่วนลด, สินค้าเพิ่ม, ดีลชีวิต, ความสามารถพ่อค้า
  - เศษชีพจร → ชีวิต
  - ซื้อของที่คนอื่นประเมิน → พลังคืน (scrap)
  - ข้อมูล → เครดิต (E19, E45, E47)

**หลักฐาน:**

**ผล:**
- ผลสถานะ 8 แบบไม่มีวันเกิดในเกม
- ความกดดันท้ายช่วง (dread) ไม่มีทางลดนอกจากลาง `calm`
- ไม่มีผลเสียแบบหักเงินหรือหักชีวิตตอนท้ายช่วงที่มาจาก event

- B24 / D23: ให้ E126 "ยาหม้อเถื่อน" เป็นการเสี่ยง seeded ระหว่าง B24 กับ D23 แทนการฟื้นทันทีพร้อม D11
- D22: ผลสุ่มของ dread แบบ `tax` ในช่วงต้น และผลของการแพ้ดวล PvP (แทนการหักทันที)

### L2 ผลที่ผูกกับโอกาสขโมยใช้ไม่ได้กับ RPS และ B22 ถูกเผาทิ้ง (สูง) [อ่านโค้ด]

- **ที่มา:** server เปิด `secureEconomy` ทำให้การขโมยเป็นเป่ายิ้งฉุบ ไม่ใช้โอกาสสำเร็จ (`core2-actions.ts:133` ตัด `stealChance` ออก)
- **ผลที่ยังอ้างถึงโอกาสขโมยแต่ไม่มีผลใดเลย:**
  - B22 นิ้วเบา (+25): `startTheftDuel` เรียก `consumeStatus(p,'B22')` (`theft.ts:145`) **ใช้สถานะทิ้งโดยไม่ให้อะไร** ถ้ามีแหล่งเกิด (L1) ผู้เล่นจะเสีย buff ฟรี
  - D21 ถูกจับตา (−15)
  - ลาง `thieves-night` (+25): แสดงข้อความ "ทุกการขโมยมีโอกาสสำเร็จเพิ่ม" แต่ไม่มีผลกับ RPS
- **B21 ผู้คุ้มกัน:** `startTheftDuel` ไม่ตรวจ B21 ของเหยื่อ จึงกันการขโมย RPS ไม่ได้ ทั้งที่คำบรรยายบอกว่ากันได้
- **D21:** คำบรรยายบอก "พ่อค้าไม่ยอมใช้ความสามารถพิเศษให้" แต่ `merchant-abilities.ts` ไม่อ่าน D21
- **ข้อเสนอ (แปลงผลให้เข้ากับดวล):**
  - B22: ตาเสมอครั้งแรกนับเป็นชนะ หรือเห็นท่าประจำของพ่อค้าแม่นขึ้น
  - D21: พ่อค้าออกท่าที่แพ้ทางท่าประจำของผู้เล่นบ่อยขึ้น
  - `thieves-night`: ชนะดวลแล้วได้ของเพิ่มอีกชิ้น
  - B21: เหยื่อชนะตาเสมอ หรือยกเลิกดวลก่อนเริ่ม
  - อย่าใช้สถานะทิ้งจนกว่าจะมีผลจริง

  - จำลอง: เปิดใช้ 219 ครั้ง เทียบกับซื้อ 621 ครั้ง ส่วนใหญ่ถือไว้
- **ข้อเสนอ (ต้องให้ผู้ออกแบบตัดสิน เพราะเป็นการเปลี่ยนเจตนาเดิม):**
  - ทางเลือก 1: ของต้องสาปที่ถือไว้มีโอกาส seeded (เช่น 15%) ทำให้เกิด drawback ของชนิดนั้นตอนท้ายช่วง ทำให้การตรวจคำสาปและ cleanse มีค่าสำหรับทุก route
  - ทางเลือก 2: ของปลอมให้ผลตอนถือครึ่งเดียว ทำให้การตรวจความแท้มีค่ากับสายถือ
  - ทั้งสองทางต้องใส่หลัง config ใหม่เพื่อรักษา replay

### L4 ช่วงสุดท้ายของ classic ทำให้ผลของบางชนิดหายไปเงียบ ๆ (กลาง) [อ่านโค้ด]

- `grant` ไม่ให้ B09, D04, D07 เมื่อเป็นช่วงสุดท้ายของ classic (`mechanics.ts:88`)
- **ผลที่ไม่บอกผู้เล่น:**
  - เปิดใช้ `sun-cell` หรือ `merchant-canteen` (buff B09) ในช่วงสุดท้าย: เสียพลัง 1 ไม่ได้อะไร ถ้าเป็นของใช้หมดก็หายไปด้วย
  - ของต้องสาปที่ drawback เป็น D04 หรือ D07 (`key`, `rift-mirror`, `echo-charm`, `tax-order`, `guild-badge`): เปิดใช้ช่วงสุดท้ายแล้วไม่มีผลเสียเลย
- **ข้อเสนอ:** ช่วงสุดท้ายให้ผลแทนทันที (B09 → ฟื้นพลัง 2 ทันที, D04 → เสีย 2 เครดิตทันที, D07 → D02) หรือปิดปุ่มเปิดใช้พร้อมเหตุผล

### L5 ระบบที่ bot ไม่แตะ ทำให้ route และสถานะไม่ถูกวัด (กลาง) [sim]

| ระบบ | ใน 48 runs | สถานะที่ผูกอยู่ |
| --- | --- | --- |
| ขายของให้พ่อค้าที่ตามหา (wish) | 0 ครั้ง (รับสัญญา E73 ไป 161 ครั้งเมื่อวัดรอบก่อน) | B16 |
| ล้างคำสาป (cleanse) | 0 ครั้ง | B16, D16 |
| ขาย Dark Market | 8 ครั้ง (ซื้อ 621 ครั้ง) | B13, D13, B17, D17 |
| ขโมย / คลัง / เงินกู้ / ตรา | 0 ครั้ง | B21, B22, D21 |
| ของค้างโดนโทษพ่อค้า | 475 ครั้ง | |

- bot ไม่มีโค้ด `wish-sell` หรือ `cleanse` (`simulation/appraisal.ts`) และขาย Dark Market เฉพาะเมื่อของตรงคำสั่ง (`:149`)
- ผล: สถานะเหล่านี้ถูกให้ แต่แทบไม่มีโอกาสทำงานใน simulation (D13 ถูกให้ 57 ครั้ง B13 15 ครั้ง)
  - การปรับสมดุลจาก simulation จึงไม่ครอบคลุมเส้นทางเหล่านี้
- **ข้อเสนอ:**
  - ให้ bot ใช้ wish-sell, cleanse, ขาย Dark Market และขโมยตาม policy
  - เพิ่ม metric "สถานะที่ให้แล้วถูกใช้จริง / หมดอายุทิ้ง" ใน `simulation/balance.ts`

### L6 pool สุ่มแคบ ทำให้ seed หลากหลายน้อย (กลาง) [อ่านโค้ด]

- สัญญาตลาด (`market-contracts.ts:19-20`): โบนัสสถานะมีแค่ B03 และค่าราคาเต็มแบบสถานะมีแค่ D01
- pool สุ่มพร/ผลเสียของ NPC และ boon draft จำกัดที่ B01–B20/D01–D20 (L1)
- debuff จากการฝากขาย (consign) มี 4 ตัว (+D17/D18 เมื่อเปิด polish)
- **ข้อเสนอ:** ให้สัญญาตลาดสุ่มสถานะจาก pool ที่เข้ากับหมวดสินค้า (seeded) เช่น ขายดาบได้ B04, ขายยาได้ B24 (ข้อเสนอนี้ต้องการ L1)

### L7 ผลจาก bond event ไม่ปรับตาม rarity (ต่ำ) [อ่านโค้ด]

- การเปิดใช้คูณผลด้วย `itemEffectScale` (rarity และสำเนา)
- `applyGain` ของ bond (`brokerage.ts:66-73`) ให้สถานะที่ power 1 เสมอ และไม่ดูว่าของที่ถือเป็นระดับไหน
- **ข้อเสนอ:** ใช้ `itemEffectScale` ของชิ้นที่ทำให้ bond เกิด เพื่อให้ของหายากมีค่าต่อ route bond ด้วย

### L8 โปรไฟล์ผลซ้ำกันในระบบหลัก (ต่ำ) [อ่านโค้ด]

- `truth-lens` = `doubt-lens` (ถือ: ตรวจความแท้ฟรี, เปิดใช้ B04, คำสาป D03)
- `bone-key` = `whetstone` (ถือ: ส่วนลด, เปิดใช้ B03, คำสาป D01, ใช้แล้วหมด)
- ทั้งสองคู่ต่างกันเฉพาะในระบบรอง (doubt-lens ใช้ท้าทาย, whetstone ใช้ล้างคำสาป) ตามหลัก "RNG content must differ mechanically" ควรให้ผลหลักต่างกันด้วย

ทุกข้อใช้ hook ที่มีอยู่แล้ว ไม่ต้องสร้างระบบใหม่ทั้งชุด

| # | ข้อเสนอ | ผลต่อ route | ใช้ของที่มีอยู่ |

## 4. ลำดับแก้ที่แนะนำ

1. **L2 ส่วนที่เป็นบั๊กชัด:** หยุดเผา B22 ใน `startTheftDuel` และอย่าแสดงผลของลาง `thieves-night` ว่าใช้ได้กับดวลจนกว่าจะมีผลจริง
2. **L1 + R1:** ต่อแหล่งเกิดของสถานะ v0.6 ทั้ง 8 ตัว แล้วแปลงผลที่เกี่ยวกับขโมยให้ใช้กับดวลได้ (L2 ที่เหลือ)
3. **L5:** ให้ bot ใช้ wish, cleanse, ขาย Dark Market และขโมย แล้วรัน simulation ใหม่ก่อนปรับตัวเลข
4. **L4:** ผลแทนในช่วงสุดท้ายของ classic
5. **ให้ผู้ออกแบบตัดสิน:** L3/R4 (คำสาปของที่ถือ), R5 (Collector สุ่มหมวด), R2/R8 (ลางกำหนด event)
6. **L6, L7, L8:** เพิ่มความหลากหลาย

## 5. เทสต์กันถดถอยที่เสนอ

- **ทุกสถานะต้องเชื่อมครบ:** ทุกตัวใน `ALL_STATUS_IDS` ต้องมีทั้งแหล่งเกิดและจุดอ่านภายใต้ config ของ server
  - ทำแบบเดียวกับ `tests/appraisal-event-choices.test.ts` ด้วยการเดินตารางข้อมูลและ simulation
  - เทสต์นี้จะ fail ทันทีกับ L1
- **สถานะต้องไม่ถูกใช้ทิ้ง:** ไม่มีสถานะใดถูก `consumeStatus` ในเส้นทางที่ไม่อ่านผลของมัน (จับ L2)
- **ลางต้องมีผลในห้องปัจจุบัน:** ทุกลางที่เกิดได้ต้องมีผลกับกติกาที่เปิดอยู่ (จับ `thieves-night` ใต้ secure economy)

## 6. สิ่งที่ไม่ได้ครอบคลุม

- ไม่ได้ตรวจตัวเลขสมดุลของแต่ละสถานะหรือสินค้า
- ไม่ได้เปิด UI ดูว่าแต่ละผลแสดงถูกต้องหรือไม่
- ข้อสรุปจาก simulation มาจาก bot policy เดิม ซึ่งไม่ครอบคลุมหลายระบบ (L5)
