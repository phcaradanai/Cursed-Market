# เครดิตหลังซื้อขายทุกช่วงและข้อมูลประตูก่อนตัดสินใจ

2026-10-14 · เวอร์ชัน Survival ล่าสุด: http://192.168.10.150:3110 · สร้างห้องใหม่

## การเปลี่ยนแปลง

ผู้ใช้ยืนยันว่ารางวัล 10/15 เครดิตและหัวก้อยต้องเกิดหลังซื้อขายทุก encounter ก่อนเลือกประตูครั้งถัดไป ระบบ TRADE → REVEAL เดิมจ่ายระหว่างเกมอยู่แล้ว จึงทำจังหวะนี้ให้ชัดในกติกาก่อนเริ่ม ปุ่มจบซื้อขาย ข้อความยอดเติม ชื่อช่วง และหน้ารับเครดิต ไม่เปลี่ยนการชำระเงินหรือสุ่มผลย้อนหลัง Server ส่ง roundRewardBase เมื่อเปิดกติกาเติมเงินเท่านั้น

E01/E08/E10 แสดงพ่อค้าทั้งสามรายพร้อมภาพ ของที่อาจมี นิสัย และความไว้ใจส่วนตัวก่อนตัวเลือก แต่ละตัวเลือกใช้ชื่อ NPC และบอกต้นทุน/ผลต่อประตู ตัวอย่างสดตรงกับผล resolver รวมประตูที่ปิดอยู่ก่อน E08 เลือกได้รายเดียว ส่วน E01/E10 รักษาสิทธิ์เลือก ไม่ได้เข้าร้านทันที ไม่แสดงตัวเลือก decline ซ้ำกับ switch ซึ่งให้ผลเดียวกัน

## หลักฐาน

- npm test: ผ่าน 423/423 รวม HTTP/WebSocket จริง
- npm run build: ผ่าน server + legacy client + appraisal client
- หลังตัดตัวเลือกซ้ำ: ทดสอบส่วนที่เกี่ยวข้องผ่าน 77/77 และสร้าง appraisal bundle ใหม่ผ่าน
- Regression เปรียบเทียบตัวอย่างกับ resolver ทุกตัวเลือกของ E01/E08/E10 ทั้งไม่มีประตูปิดและปิดแต่ละบานไว้ก่อน พร้อมตรวจ SSR ว่า NPC ทั้งสามมาก่อนแบบฟอร์ม
- ซื้อสินค้าในช่วง 1 และ 2 ของ Survival ได้รางวัล 10/15 ก่อนพบพ่อค้าต่อไป เกมยังไม่จบ แล้วเล่นต่อจน Collector เพื่อยืนยัน audit replay ตรง
- Socket regression ซื้อสินค้าจริงทั้งสองช่วง รับเงินเข้ากระเป๋าแล้วเข้าสู่ช่วงถัดไปพร้อมยอดเงิน

- Browser บน fixture ที่ระบุ E01 ใช้ production bundle: เห็น NPC ครบก่อนเลือก เปลี่ยนเป็นปิด Orc แล้วตัวอย่างลดจาก 3 เหลือ 2 ประตู และปิด Orc จริง; เดินไปจบซื้อขายช่วง 1 พบหน้า 10 เครดิต กดรับแล้วกระเป๋า 40 → 50
- Desktop 1440×1000 และ mobile 375×900: ข้อมูลประตูไม่ล้นแนวนอน ปุ่มยืนยันสูง 44px และเลื่อนถึงได้
